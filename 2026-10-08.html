M. @wlzh

GPT-6 开始全面推送了，覆盖"每周超过 12 亿"的 ChatGPT 用户。这次真正的看点不是模型变强了多少，是一个叫 Intelligent UI 的东西：回答不再只是一堆字，可以直接带出图形、按钮、表单、图表，甚至现成的交互工具。

逻辑很简单粗暴。问对比类问题，给你并排呈现；问原理类，给交互式图解；问简单的，还是纯文本。一句话：什么问题配什么形式。

技术上分两层，都在解决过去生成式 UI 的硬伤。第一层是原生可流式组件库，不让模型现场写代码，而是给它一套统一的组件，模型只管选哪些、怎么拼，跨 Web 和移动端体验一致，速度也快。第二层是界面编译器，模型边生成边渲染，不用等整个回复写完才出界面。之前这类产品的最大痛点就是延迟，这个算治本。

训练方法也跟着变：生成的界面按清晰度、有用性、完整性打分，模型自己学会什么时候该上交互、什么时候纯文本就够。OpenAI 自己都说"模型的设计判断仍需改进"，这话挺诚实的。

演示里几个场景还挺能打：烤肉计划直接带时间轴和食材用量表；自驾游路线落在地图上；中心极限定理、Monty Hall 问题都能交互着讲，改输入看结果变化；账单分摊、退休储蓄计算器、小游戏随口一说就造出来。

最扎心的是对比。同样问"周日烤羊腿"，GPT-5.6 给你一大段文字，GPT-6 直接甩出一个完整界面：人数调节器联动购物清单，烹饪时间线还能勾选。Adam.GPT 转发时那句"Dynamic, generative UI"，兴奋都快溢出来了。

howie.serious @howie_serious

agent 范式下让人不适的真相：人的理解才是真正的瓶颈。（而不是 agent 和模型能力）

如推文所说，常见的失败模式是：人们在自己专业领域之外做事时，不知道怎么把 prompt 和计划写得精确，结果只能靠大量轮次"模糊地反复迭代"，既费时又费 token。

解法很简单：直接让模型先教你不懂的东西。

核心结论：ai 编程的瓶颈不在模型能力和 agent 能力，而在使用者能否精确表达需求。领域知识决定了表达的精度；缺知识时，先让模型补课、再动手，比盲目迭代高效得多。

The client didn't want AI anywhere near their systems. So AI never touched production.

I've watched teams get this backwards across dozens of engagements. They bolt a model onto scattered data, watch it guess, and decide AI isn't ready for their industry. The data work is what makes it ready.

Then we built the middleware: 23 data models, permissions down to table, row and column, and no database credentials handed out. One controlled door to the warehouse.

Every table follows one pattern: AI drafts the documentation, a validation script has to pass before anything is published, and production DDL overrides everything. If the doc disagrees with production, production wins.

→ Transaction changes every 5 minutes against a 24-hour target → Key query from 68s to 3s against a target of under 10 → Full load from ~4 hours to 30–50 minutes → ~97% lower processing cost on unified transactions → 401 transaction attributes decoded into clean, masked columns

Most teams hand over a platform and hope the client can run it. We tested it. One of their data engineers migrated a table on their own, using only the AI-generated how-to.

Their head of DevOps then asked for our AI setup. We handed over the skills and agents along with the platform.

The model was never the hard part. The foundation was.

That's the line between a company that's ready for AI and one still stuck on its data.

开头还好。

问题通常出在两个任务都跑了一段时间之后。其中一个会给你一个情况，需要你真正理解上下文，然后给出清晰的指令它才能继续走。但那个时候我的大脑其实飘在另一个项目上，甚至更糟，飘到因为等待 AI 处理时无聊去刷的 Twitter、读 newsletter,或者做其他杂事上。
