同一个 Claude 三档设置怎么选：prompt（零设置、每次从头）/ project（约 5 分钟，存文件和指令）/ skill（约 15 分钟，教一次反复用）

Alex Prompter @alex_prompter

Same AI, three levels of setup, and choosing the wrong one means you either repeat yourself or over-build something you use once. The difference comes down to what Claude remembers, and when it runs.

A prompt is type it, get an answer. It needs no setup and works in any chat or Cowork session, but every new chat starts blank and Claude only matches your tone if you explain it each time. It is best at speed, and it is also the only one of the three that never saves tokens.

A project is add files, keep context. Setup takes about five minutes, creating a project, uploading files, and adding instructions. Claude remembers them inside that project, but it only helps when you open the project. It is best at context, and it saves tokens somewhat.

A skill is teach once, use forever. Setup takes about fifteen minutes with the skill creator, answering its questions and saving the skill. It lives in Cowork under Settings, Capabilities, then Skills, and runs automatically when Claude recognizes the task. Your voice rules can be part of the skill, so tone stays consistent. It is best at consistency and it does save tokens.

Choose a prompt for a one-off task when you need a fast answer and no saved context. Choose a project when you work with the same files again and again and want one shared workspace. Choose a skill when you repeat the same instructions often and want reusable processes.

If you have typed the same instructions more than three times, that is a skill waiting to be built.

Bookmark this before you type the same instructions into Claude a fourth time.

Claude Code 团队的九成代码都是 AI 写的，他们是怎么审查代码的？

如果 AI 替你写作业，一天写一千份，老师批得过来吗？写代码的公司，现在就碰上了这件事。

Claude Code 是 Anthropic 做的编程助手。它自己的代码，大约九成是 Claude 写的。Anthropic 全公司的代码库，九月份一天要合并三万多次修改（五月份还是每天 2500 次左右）。靠人一行一行看，根本看不过来。

可 Claude Code 团队说，从六月到九月，他们合并的修改翻了一倍多，需要撤回的比例反而降了四成多。看的人少了，错反而少了。这是怎么做到的？

【什么是代码审查】

先说程序员平时怎么防出错。改完代码，不能直接放进产品，要先交一份修改申请，英文叫 PR（Pull Request）。同事一行一行看，挑毛病，点了头才能合并。这叫代码审查。

就像作文交上去，老师批过，才能贴上墙。

合并以后才发现出了问题，就得把修改撤回来。撤回得越多，说明漏掉的错越多。

【一摞带洞的奶酪】

Claude Code 团队觉得，“有没有人读过代码”，这个问题问得太粗。更该问的是：这一次修改可能出什么错？哪一道检查最适合拦住它？

可以把每一道检查想成一片带洞的奶酪。每一片都能挡住一些错，也都有洞，会漏掉一些。好几片叠起来，洞很难对齐，错误就很难一路穿过去。最底下再铺一张网，真漏下去了，也能很快捞回来。

这一摞奶酪里，大部分片是机器。人的时间最珍贵，它花在两头：一头是审代码，一头是出了事去救火。只省前一头，救火的时间涨上去，等于没省。所以他们盯着两个数：人花了多少时间，撤回和事故有没有变多。

【跟着一次修改走一遍】

从作者的电脑到用户手里，一次修改走的是一条流水线。前面那几片奶酪，就排在这条线上。

上流水线之前：自己先验。 代码还在自己电脑上，没有提交。Claude 写完代码，要自己跑测试、编译、做代码规范检查，把结果摆出来

Claude Code 团队公开了他们审代码的做法：代码大约九成由 Claude 写，六月到九月合并的修改翻了一倍多，需要撤回的比例反而降了四成多。

这期用一摞带洞的奶酪片讲这套做法：每道检查都会漏，叠起来就很难漏，底下还有一张网兜底。

片中回答五个问题：哪些修改还要人看，AI 审 AI 会不会没完，审查的 AI 漏了怎么办，人不读代码怎么懂代码，出了事算谁的。人不再逐行读代码，时间花在机器做不好的判断上。
