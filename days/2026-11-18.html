YC 访谈：在 Slack 里把功能交给 AI 队友，并开源 pstack

Mai Yang @MaiYangAI

Lauren Tan × Roman Ugarte：你能创建 AI 队友

Y Combinator 的 Lightcone 请来 Grok Bot 团队的 Lauren Tan 和 Roman Ugarte。他们在节目里说：「Grok Bot 这款产品，让你能创建 AI 队友。」他们说这是认真的，可以把实际工作分配给这些队友。

Lauren 有一次和同事一起，在 Slack 里让工程 bot 从头到尾做完一个功能。那个 bot 自己去启动了 Cursor Cloud Agent，那是带虚拟机和自己电脑的 agent，能在自己的电脑上运行 Grok Bot 做原型，带着视频和截图回来。这个项目她甚至都没打开 Cursor。全程都在 Slack 线程里完成，同事也可以加入讨论。她开源了 pstack，它受到 gstack 的启发，放在 Cursor 的插件仓库里，用来教 agent 像她当年写代码那样，严谨地做工程工作。他们也讲到，要教 agent 检查自己写的代码，发现问题后再改，直到产出你想要的结果。这样并不保证代码质量一定好，但可以做到你想做的事，只是可能很慢，或者特别浪费资源。功能可以很快做出来，但瓶颈已经不太是做这些功能要花的时间。产品方向和怎样算好，还是由团队把关。他们会在发布前跟改动多相处一阵，久到甚至有点不自在。内部都没找到产品市场契合，或者内部反馈有好有坏，就不发布。即便做得很快，也不意味着把想到的每个功能都发布出去。

这是约 60 分钟的完整访谈，中英字幕，从创建 AI 队友、在 Slack 里把功能做完，聊到 pstack，以及产品判断该卡在哪里。直接看。

Hugging Face 给 Qwen3.8-27B 配 pi coding agent LoRA：最难 51 题 29.4%→62.7%

yibie @yibie

给一个 coding agent 单独训练模型

Hugging Face 给开源模型 Qwen3.8-27B 配了一个 LoRA，只在 pi 这个 coding agent 里用强化学习训练，不动基座权重。

做法上有两个值得看的点。训练在没改过的 pi 里跑，模型每发一次工具调用，中间的 safeagents 代理先用规则查一遍，明显在钻奖励空子的调用直接拦掉、记 0 分。任务是从公开 agent 会话重建的可验证环境，分修 bug、问答、从零搭建、扩展代码四类，对错由任务自带的验证器判，不靠人打分。奖励里还专门加了一项：答对的前提下工具调用越少加分越多。

效果是准确率和效率一起涨。SWE-bench Pro 最难的 51 题，基座模型 pass@1 是 29.4%，适配器到 62.7%，工具调用少 55%。Terminal-Bench 2.1 从 39.5% 到 55.8%，工具调用少 62%。评测是同任务配对、温度 0.8、关思考，显著性也给了。

模型卡里有个真实例子：同一个 SWE-bench 任务，基座反复搜索、重跑片段，撞到 100 步上限没过；适配器找到函数、改掉、跑测试、补最后一个用例，一共 8 次调用。

我觉得真正的信号是 LoRA 把适配成本压到了小团队够得着的程度：不用重新训一个 agent 模型，给自家工具和 harness 单独训一个小适配器就行。权重已经开放，vLLM、llama.cpp 都能挂。

两点保留。数字都是 Hugging Face 自测，没有第三方复现；最终检查点是看着评测子集的分数挑的，而且训练计划 1000 步、第 191 步就提前停了。

开票之前，它先核对合同，客户漏了 VAT 或 GST 税务识别号，就通知销售补材料。

B 端记忆框架三点：合规隐私、成本定制、私有部署，暂无仓库或步骤

Elliot 艾略特 @ElliotChen

最近记忆框架的热度又起来了。上半年印象里还只有少数几个，现在 GitHub 上随便翻翻，能找到好些个不错的。

记忆这事儿吧，要做不难，要做好却又不容易。

现在不少云平台都在搞自己的记忆，本来是想搞成一个核心功能，但如果跟业务收入联系不够直接，资源就不好分配，搞着搞着就容易变成锦上添花，不再更新。

反而是我们在对接 B 端的时候发现了一些共通性，也不复杂，就 3 点：

1. 合规和隐私。 2. 成本和定制。 3. 私有部署和规模。

合规和隐私，问得很直接，数据放哪，谁能看，怎么加密，能不能删干净。不同地区还有不同要求，也不是轻易拿个认证就都解决。

成本和定制就更具体了。知道记忆重要，但每个用户要花多少钱，数据积累半年以后要花多少钱，调用量上来以后又怎么算？在为了保证成本的前提下，取舍怎么分配等。

所以哪些内容值得记，多久整理一次，用什么模型，每次取多少，都得能按业务调整。速度和召回效果要保证，预算也得控制，不能每一步都上最贵的配置。

私有部署还得看能不能接客户自己的模型，数据和模型调用能不能都留在客户环境里。部署完也没结束，数据多了，并发上来了，速度和成本还能不能维持，后面怎么扩，都是要提前算的。

小规模跑通以后，客户还是得知道，真用起来会花多少钱，规模上来以后能不能撑得住。

Memory as a service，存在就有点道理。
