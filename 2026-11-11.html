Google Antigravity /swarm：按文件切开分给一组 Agent，每 2–4 个 worker 配一个 verifier；Preview 仅 Pro/Ultra，很吃额度

泊舟 @bozhou_ai

bozhou_ai：Google Antigravity 官宣 /swarm 蜂群模式——一句话需求，拆给一组有名字的 Agent 同时干，大家在同一块留言板上分工、提问、汇报。思路是先分地盘再开工：协调者把任务按文件、按包切开，每个 worker 只管自己那块，负责什么、不许碰什么、做到什么算完，都公开贴在板上。

核心在监理。协调者通常每 2 到 4 个 worker 配一个 verifier，读 diff、跑测试，发现问题直接退回给写代码的那个 worker 改。没活的成员在板上睡着，不耗 token，被 @ 才醒。

用法：在 App 或 CLI 里输入 /swarm，按 Tab，写清楚要做什么、怎么验证；协调者拉人分活后，App 里点 Open the Swarm UI，CLI 里敲 /swarm board 看实时看板。想让验收用另一个模型，直接写在提示词里，平时主要跟协调者说话。官方说它适合能干净切开的活，例如三个接口各加校验和测试、几个包各修各的失败用例；难而不大的问题建议用 /boost，跑好几天的仓库级迁移用 /teamwork。

/swarm 现在还是 preview，只开放给 Google AI Pro 和 Ultra。官方原话是每个 worker 都是独立 Agent，所以 swarm 用额度比单个对话快得多，CLI 菜单里还标着 Preview & Quota Heavy；成员额度用完会暂停，额度刷新后也不会自己重启。

先查公开仓库里有没有 .claude/settings.local.json：Apiiro 扫到超过 10 万个仓，1100 个里有数据库密码、API token 或私钥

M. @wlzh

用 Claude Code 的人先别急着写代码，查一下自己的公开仓库。Apiiro 扫到超过 10 万个公开 GitHub 仓库里躺着 Claude Code 的本地配置 .claude/settings.local.json。其中约 1100 个、来自 63 家机构的仓库里真有货：数据库密码、API token、root 账号、私钥。这 1100 个里有 215 个，连 gitleaks 和 TruffleHog 都没扫出来。

问题出在 “Yes, and don't ask again”：给一条 shell 命令点一次「以后别再问」，Claude Code 就把这条命令原样写进配置文件，命令里嵌着的密钥也跟着进去。Anthropic 文档说这个文件会进全局 .gitignore，一般不会被公开分享。但换台机器克隆、文件夹后来变成仓库，或 Claude Code 在没注意时提交了这个文件，照样会漏。发现后删了也可能还留在 fork 里。

这事 2025 年 8 月就有人报过 bug，60 天没动静被系统自动关上。Boris Cherny 在 Hacker News 说团队正在想办法，并建议先用 auto mode 和 secret scanner 顶着。现在就去搜自己的公开仓库，有 .claude/settings.local.json 就赶紧处理。

斯坦福 CS329Z 讲座和两份作业开源：不到 5 美元从零写一层 agent harness；第二份作业仓库实际是 assignment2-evals

宝玉 @dotey

斯坦福新课 CS329Z《Engineering AI Agents》（Diyi Yang、Michael Ryan、John Yang）开始对外公开课程资料。讲座视频每天在 Stanford Online 的 YouTube 更新，已上第 1 讲《什么是 agent 系统》和第 2 讲《写给 agent 开发者的大模型知识》。两份作业仓库 MIT 协议开源，别的学校注明出处就能拿去上课。开课时录像只放在校内 Canvas，现在课表也开始挂视频链接。

第一份作业：自己写一个 agent harness，也就是包在模型外面、负责接工具、解析回复、执行命令、管理上下文的那层。不许用任何 agent 框架，课程只给一个最原始接口（传消息、返回文字）。仓库起步测试全是失败的，任务是让它们一个个通过。88 分自动评分里有 48 分来自不调用模型的测试，跑多少遍都不花钱；真调模型的请求第二次走本地缓存，不再收费。Michael Ryan 说不到 5 美元 API 额度就能做完；讲义里的参考数字更低（参考答案跑一遍线上测试 0.05 美元，模拟用户评测再 0.18 美元），自己调试反复跑会更贵。选课学生用课程 OpenRouter 密钥，校外得自己准备，默认模型是 openai/gpt-6-luna。

第二份作业由 SWE-bench 共同作者 John Yang 出题，教用 Harbor 出一道 Terminal-Bench 风格的考题，并用 mini-SWE-agent 配 Gemini 3.8 Flash 跑五次，分析题目是否有效、贴近真实、能复现、有难度。需要 Docker，以及 Gemini 或 OpenRouter 密钥。照着第二份作业讲义克隆时注意：讲义里写的仓库名是 assignment2-harness，实际地址是 assignment2-evals。

这是一门正在上的学期课，课表还是暂定，讲座逐日公开不是一次放完。「不到 5 美元」说的是 API 额度。宝玉的长文把作业结构和评分写得更全，主帖和作业链接跟帖并在这一张卡。

1. 先盘点每轮对话都会加载的内容，包括根目录的 AGENTS.md / CLAUDE.md、全局规则、没写 paths: 的 .claude/rules 和每个 skill 的描述，看各占多少字，再看按需加载的部分，这里不少看着臃肿的内容可能不是写多了，而是放的位置不对。 2. 逐段给出处理方式，分成修、删、挪、改写、保留五种，挪的写清目的地，每条附一句原因，做成一张清单给我确认。 3. 逐句判断删掉后你的行为会不会变，把类似「先读再改」「跑测试」「注意边界」你本来就会做的描述删掉，拿不准的可以先保留找我确定。 4. 更推崇给 Agent 写目标，少写如何实现的路线，写清做完是什么样、怎么算完成、要什么证据；一个步骤删掉后你还能换条路做到同样结果就删掉，只有顺序本身是约束的才留下来，比如先验证再发布、先确认再删除。 5. 同一种要求说了三遍，换成一个你本来就懂的词语，比如「快、确定、开销小」可以写成 tight；「要简洁」这类口号换成更好理解的词，再配一组 NO / OK 例子。 6. 把对应内容放对位置：需要判断的进 skill，同样输入总是同样输出的改成脚本或 hook，项目命令和发布步骤进项目指南，跨项目的硬约束才放进全局规则；遇到「做 Y 之前先读 X」这类要求，改成做 Y 时由 hook 把 X 注入进来更好。 7. skill 描述只写做什么、什么时候用、不用于什么，近义词移到 when_to_use，只有部分场景用到的内容移到 references；判断一个 skill 有没有人用，要看真实调用记录，不要只 grep 名字，要删的也先列给我看。 8. 这些内容不要删除：我的偏好、被否掉的方案和原因、机器环境；不报错的坑，以及看着像出错其实正常的现象；描述句里「从不写入」「不上传」这类半句约束；删数据、需要花钱、要发布、提权、改写已推送历史这些不可逆操作的规则；带日期的拍板决策记录。 9. 内容先移到对应正确的位置再来压缩，能整行搬到按需加载的文件里就整行搬，不要边搬边改写，不可逆的规则原样整段搬。 10. 搬到能自己加载的地方可参考：提交、发布、回复、删除这类对话里随时会触发的规则留在根目录；挪进 docs/ 的要在根目录留一句什么时候去读；根目录不要建 CLAUDE.md，它会让 Claude Code 不再读 AGENTS.md；项目里重复全局规则的句子，只有在我用的每个工具都读全局规则时才删。 11. 改完以后自己查一遍：paths: 里的 glob 都要能匹配到真实文件，grep 一遍拆走的旧文件名，再列出所有消失的行，每一行都要对上清单里我确认过的删除。 12. 交给一个没参与精简的 Agent 查有没有删过度，只给它消失的行和仓库，不给你的结论，让它搜关键名词而不是整句，意思在哪都找不到的原样恢复。 13. 验证移过去的内容真的会被加载：在新文件里埋一个暗号，开一个新会话，先读一个匹配的文件再问它暗号，然后读一个不匹配的文件做反向对照。 14. 全部做完以后，沉淀一下这个思路，方便以后模型升级时再跑一遍。

这个内容有流量是一个结果，它不是原因
