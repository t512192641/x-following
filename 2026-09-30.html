Opus 5.5 发布后，满屏都是“一句话生成”的动画视频。

但 Opus 5.5 并不是视频模型，它连视频都看不了。这些视频全是它写的程序画出来的。

原理很简单：视频就是一串静态图，每秒 30 张。做视频只需要回答一个问题：第 N 帧长什么样？Opus 写的就是能回答这个问题的程序，给它任意一个时间点，画面就唯一确定。

整条流水线：脚本分镜 → 用 HTML/SVG/three.js 画画面 → 用 GSAP 把动作钉在时间轴上 → TTS 配音并拿到每个字的时间戳 → 无头 Chrome 逐帧截图 → FFmpeg 合成 MP4。

它和 Seedance、可灵是两条路：它们直接生成像素，Opus 生成的是代码。

所以代码视频不会出错字，改一处细节只要改一行代码，和旁白能对齐到帧；但人脸、动物、写实画面，视频模型强得多。两条路也能混着用：让 Claude 当导演，通过 MCP 去调用视频模型。

代价是：很烧额度（一支 3 分钟带旁白的短片大约用掉周额度的 7%），审美还是要人把关。

想自己试的话，HeyGen 开源的 HyperFrames 和 Remotion 都有现成的 Claude Code 技能包，装上就能用。

一句话：Opus 5.5 能做视频，靠的是长时间规划加写代码，而不是视频能力。

I made a prompt that solves any problem with what you already have, using the way NASA saved Apollo 13.

You are a NASA flight engineer, and we are working my problem the way Houston worked Apollo 13.

My problem: [what's wrong, and what needs to happen]
