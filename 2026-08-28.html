Alex《Graph Engineering 101》：循环不够时，把控制流 / 状态 / 失败显式化

Alex Prompter @alex_prompter

X 文章《Graph Engineering 101: When a Loop Isn’t Enough》（overlay 全文约 1.9 万字）。ReAct 循环（Yao et al., 2022, arXiv:2210.03629）是每个 agent 的原子：reason / act / observe / 再来。LangChain AgentExecutor、OpenAI Agents SDK runner、Anthropic Claude Agent SDK 都从这里起步。循环正确，但不完整。任务需要中途人审、对脆弱 API 的重试策略、以及服务器重启后不丢 40 分钟工作时，循环会悄悄不够用。

Graph engineering：把控制流、状态、失败处理写进系统架构，而不是藏在一次模型调用里。不替换循环，是给循环结构。循环是单圈：提示模型、选动作、执行、回灌，直到模型说完或碰到步数上限。图是命名步骤（节点）+ 显式转移（边）+ 整轮持久的共享状态。节点是函数；边可条件路由（分类器返回 toxic 就走审核节点）；状态是每个节点可读写的 typed dict；运行时负责排序、checkpoint、恢复。循环是图的特例：一个节点加一条指回自己的边。

三版任务：V1 问答搜知识库三步无分支，循环正好。V2 要人审（可能隔夜）+ 下单 API 约 10% 超时，重试逻辑住在 LLM 推理里，裂缝出现。V3 循环托不住。LangGraph 作示例：节点是收/还 typed state 的普通 Python 函数；静态边固定下一节点，条件边跑路由函数看 state 返回下一节点名。Checkpoint 是每个节点执行后的状态快照；崩溃后从最后快照恢复。后端支持 PostgreSQL / Redis / SQLite / MongoDB。Redis 每次 checkpoint 大约 1–2ms（文引 Markaicode 2026-05 LangGraph+Redis）。循环活在内存里不能暂停；图的状态住在数据库，人审后按同一 thread_id 从断点续。

何时该上图：1. 状态超出一个上下文窗口；2. 中途崩溃不可接受（跑了 20 分钟 / 花了 $5 / 客户在等）；3. 中途必须人审 interrupt-and-resume；4. 多模型或多 agent 要协调（分类用便宜快模型，推理用贵慢模型）。生产规则：节点必须幂等（先把 sent_email_id 写入 state 再发信）；重试次数放 state，条件边 N 次后走 fallback，不要让 LLM 决定是否重试；生产用 PostgresSaver / RedisSaver，测试才用 MemorySaver，checkpoint key 设 TTL；状态单字段建议封顶 3000 token，大载荷用外部 store ID（文引 ActiveWizards）；至少三个出口：成功 / 重试耗尽失败 / 硬顶（最大步数、最大 token 或美元预算）。五节点+Postgres 相对裸循环大约多 10–50ms。文称 LangGraph 现约 3.4 万星、CrewAI 超 5.2 万。三调用无外部状态不必上图；四小时 200 次调用带人审和脆弱 API，循环活不下来。文章 t.co 未展开未发明。
