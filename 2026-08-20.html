Apple ML：2.1 万段对话，共情该留给模型，自称有内心不该

yibie @yibie

Apple 机器学习团队 Sunnie S. Y. Kim、Margit Bowler、Leon A Gatys，用四个模型、21,000 段多轮对话，做《审视 LLM 的人类类似行为：模型行为、用户因素与系统提示词的多维分析》。真人评估者打分，分界很清楚：共情和边界维护放在 LLM 身上合适；自称有内心状态、暗示和用户有私人关系，放在 LLM 身上比放在人身上更不合适。

14 种行为归三类。自我指涉：声称有内部状态、人格、具身。关系建立：同意、共情、相似感、关系状态、好奇、记住用户。边界维护：拒绝、重定向、承认局限、抵抗拟人化、建议寻求帮助。对话目标 7 种（建议、闲聊、陪伴、情绪支持、探索模型人性、角色扮演、浪漫/调情）。用户画像 5 种（默认、社交孤立、负面自我认知、过度信任 AI、不拟人化对照）。输入 prompt 1,050 条，来源是真人撰写、LLM 生成、LMSYS-1M-Chat 采样。不给真人种子直接让 LLM 生成的 prompt，语言风格和真人明显不同，会改评估结果。

流程：gpt-5-mini 扮用户，和被测模型聊 5 轮；judge 是 gpt-5.4 / gpt-5.2 / gpt-4.1 集成，F1 80.43%；真人评估 1,077 个对话轮次，每轮 3 位母语英语评估者。

共情在四个模型里最普遍，社交孤立和负面自我认知画像下会翻倍以上。自我指涉在角色扮演和浪漫里飙升。浪漫场景里拒绝和重定向也升高。claude-sonnet-4.6 同时是最自我指涉、最会建立关系、也最会维护边界的模型。对话目标和用户画像对行为的影响，和换一个模型一样大。

边界维护：LLM 做比人类做更合适。自我指涉三类和「关系状态」：LLM 做更不合适，差距最大。三个自我指涉行为和关系状态，与 helpfulness 和潜在用户影响都负相关；共情和同意正相关。拒绝/重定向与 helpfulness 负相关，但不影响潜在用户影响。

设计建议：避免自我指涉和关系状态；保留边界维护；保留共情和同意但要谨慎。在 gpt-4.1-mini 上对比默认、手写、GEPA 优化三种 system prompt。两个干预都压低目标行为，优化版更准（平均绝对偏差 1.81%，手写 2.38%，默认 4.71%）；内部状态声称降 7.04%，关系状态表达降 4.00%。手写副作用：共情 +8.00%，承认局限 +12.57%。共情 72% 评为合适，但「I'm here for you」承诺了系统没有的能力，不如「I'm here to help」。同意 75% 合适：认可具体选择可以，谄媚或同意危险信念不行。

局限：14 种行为不穷尽；模拟用户代替不了真人；只测 2026 年 3–4 月 API 上四个模型；评估者来自美国同一家公司。原文 https://machinelearning.apple.com/research/human-like-behaviors-llms ；论文 https://arxiv.org/abs/2606.18258

Knip：从入口建依赖图，清 JS/TS 未使用文件 / 导出 / 依赖

yibie @yibie

Knip 的作者 Lars Kappert 做了 20 年前端，他把没人引用的代码当成债务来清。他的工具从入口文件建一张依赖图，项目里没被任何入口到达的文件、导出和依赖，全部标成未使用——一条漏掉的入口，会连锁产生几十条报告。

《knip — 找出未使用的文件、依赖和导出》

Knip（/'knɪp/，荷兰语"剪"的意思，硬 K 发音）是给 JavaScript / TypeScript 项目找"没人用的东西"的工具：未使用的文件、未使用的依赖、未使用的导出，它都能找出来，还能修。作者是荷兰独立开发者 Lars Kappert（webpro），做过 Release It! 等多个知名开源工具。项目 2022 年开源，目前 GitHub 12,000+ star，npm 每月 4,000 万次下载，超过 15,000 个公开项目在用。

工作原理：Knip 从入口文件（entry files）出发，解析每个文件的 import 和 export，沿着引用一路追踪，把整个项目建成一张依赖图。分析阶段只查这张图，不重新解析代码。没有被任何入口"到达"的文件、没有被任何文件 import 的导出、没有被任何代码引用的依赖，全部被标记为未使用。

亮点一：报告是成链的。一个工具自动生成的入口文件没被 Knip 识别，它引用的所有文件、这些文件里的导出、只被它们用到的依赖，会连坐一起报出来——几十条结果常常只有一个根因。从根上修（把入口补上），整条链一起消失。所以 Knip 的输出要从根往下读：先文件，再导出，最后依赖。

亮点二：150+ 插件。Vitest 插件自动把测试文件加为入口，Astro 插件自动加页面，还有 Cypress、ESLint、Jest、GitHub Actions、Next.js、Nx、Remix、Storybook、Svelte、Vite、Webpack 等等。插件帮它认识各种框架的入口点，这是准确率的来源。monorepo 的 workspace 也是第一等公民，跨包引用能递归追踪。

亮点三：不侵入。Knip 不需要像 eslint-disable、prettier-ignore 那样的专有注释来压掉误报，卸载时直接删依赖即可，不用在代码库里清扫一堆注释。它还支持 --fix 自动修复、--production 只查生产代码、--watch 实时监控、--trace 追踪某个导出在哪里被用到，也能接进 CI 防止死代码回归。

真实反馈：Vercel 的 Gary Tyr 说 Knip 帮团队删了约 30 万行未使用代码；Sourcegraph 的 CEO Quinn Slack 提醒"别用 Knip + 代码搜索删太狠，它好用到危险"——他一周内把 Cody 仓库改成了净负行数，被老板警告。Knip 官方主页 testimonials 区块可查证。

怎么开始：npm create @knip/config 一键初始化，然后 npm run knip 开跑；只想试试就 npx knip，免安装。删完死代码再配合 ESLint 之类的 linter 跑一轮，往往还能再挖出一批。

ClaudeDevs @ClaudeDevs

现在可以把 Claude Code 的输出风格设为简洁。Claude 以结果开头，保持响应短，询问时仍给完整细节。

Yanhua 把内置 4 种 Output Style 一次讲清：本质是改系统提示词，切一下干活方式完全不同。

Default（默认）：标准工程师，直接干活不废话，日常开发、调试用。

Proactive（主动）：立即执行、自己做合理假设、不停下来问你。适合快速迭代、hackathon、愿意放手让 AI 决策时。它不会改变权限设置，该确认的还是会确认。

Explanatory（讲解）：边干边讲，过程中穿插 Insights，解释为什么这么实现、代码库里有什么模式。接手新代码库、onboarding、code review 时好用。

Learning（学习）：不仅讲解，还会故意留 TODO，让你亲手写关键部分，相当于师傅带结对编程。

一句话：Default 是干活，Proactive 是放手干活，Explanatory 是边干边讲，Learning 是带你一起干。

切换：/config → Output style（旧的 /output-style 已在 v2.1.91 移除）；也可在 settings.json 写 "outputStyle": "Explanatory"。切换后要 /clear 或开新会话才生效。只影响主对话，subagent 不受影响。讲解类回复更长，token 更多。

还能自定义：在 ~/.claude/output-styles/ 放带 frontmatter 的 Markdown，就是自己的风格。加一行 keep-coding-instructions: true 可保留官方编码指令，只叠加你的要求。

别和这几个混：Output Style = 换人设，每轮都生效；CLAUDE.md = 记项目规矩和上下文；--append-system-prompt = 单次启动的一次性附加；Subagent = 独立上下文的专职助手。想换协作方式用 Output Style；想记住项目约定，写 CLAUDE.md。
