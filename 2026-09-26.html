Claude Code 任务做到一半撞上 5 小时限额时，会先找个合适的地方停下，不再改代码改到一半就直接断掉。收尾用的是一小笔固定额度，从你的每周额度里扣。

Claude 的付费订阅有两道限额。一道是滚动计算的 5 小时窗口，从你发出第一条消息开始计时，管短时间内能用多少。另一道是每周总量上限。网页版、桌面端和 Claude Code 共用一个额度池，在哪儿用都算。

以前 5 小时额度一用完，Claude Code 当场就停。如果它正在做一个跨多个文件的改动，停下来时可能 5 个文件只改了 3 个，代码连编译都过不了。几个小时后额度恢复，你得先弄清楚它停在哪、改了哪些，才能接着往下做。

受益最大的是让 Claude Code 长时间自己干活的人，比如开个大重构然后去开会，或者睡前丢给它一个长任务。以前回来可能面对一个改了一半的代码仓库，现在它会尽量把手头能收尾的部分收掉，停在一个方便接着干的位置。

推送初期的规则是：Pro 用户每周能用一次收尾额度，Max 和 Team 高级席位（Team Premium）每次撞上 5 小时限额都能用。收尾之后还想继续，可以开启额外用量（extra usage），超出部分按 API 标准价格另外计费。

1. 它把复杂的智能体做成了消费产品 很多智能体需要用户配置工作流、权限和工具。 Muse 直接进入应用和 WhatsApp，用户像发消息一样交代任务。邮件、日历、社交账号、购物和支付可以逐项连接。Meta 想把原本面向开发者和专业用户的能力，交给没有技术背景的普通人。

2. 它把长期任务做成了看得见的页面 Grok Bot 也能长期运行，Muse 在产品界面上又向前走了一步。 目标页面显示正在推进什么、计划是什么、完成到哪里；活动记录展示它做过哪些操作； 记忆文件允许用户查看和修改； 行程表、仪表盘等交互式成果可以长期更新。

用户不用在几百条聊天记录里寻找项目状态。

3. 它给高权限智能体加了更重的安全边界 Muse 运行在每位用户独立的安全虚拟机（Muse Secure VM）里。 密码、支付信息和连接器凭证不会直接交给主模型。 所有对外请求还要经过独立安全智能体 Sentinel 审核。 发送邮件、付款等敏感动作会停下来等待用户批准。

这套架构仍然不能消除提示词注入和误操作，但能限制一次错误造成的影响。

4. Meta 有能力把“回答”接到真实交易 Muse 可以浏览网页、填写表单、发送邮件，也能通过支付服务完成购买。 再加上 Facebook、Instagram 和 WhatsApp 的用户关系与内容，Muse 获得了大量个人生活上下文。 它可以从保存的食谱生成购物清单，记住朋友的饮食限制，再处理邀请和采购。这个闭环是 Meta 最有分量的资源。

所以，把 Muse 叫成革命性新智能体有点过头。它沿用了 Computer Use 和常驻智能体的发展路线。 它的价值来自产品整合、安全架构和 Meta 的消费生态。

Grok Bot 更接近数字员工，Muse 想成为普通人的数字管家。
