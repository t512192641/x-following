我整部片子的花费，95秒，还不到它的三分之一。

如果无脑一点，这批镜头全用 SD2.5： · 1080p：约 8,700 积分 · 720p：约 3,700 积分 · 480p：约 1,570 积分 实际视频生成只花了 1188，比第一种便宜 7.5 倍。

省在哪？我给 Claude 定了两条规矩：

一、模型按需选。 业火、焚书、炎龙这类特效重的高潮镜头才上 SD2.5；回头、系红绳这类人物表演用 SD2.0；孟婆一个凝视用 Fast，只要 23 积分。

二、生成只出 480p。 放大到 1080p 甚至没用超分模型，就是代码里写的普通插值。80 年代港片本来就是软焦加胶片颗粒的质感，颗粒一铺，分辨率的差距正好被藏住了。

SD2.5很好，但也很贵，但并不意味着所有镜头都需要用SD2.5才能生成，按需选择，积分要花在刀刃上。

Cal AI 18 个月做到健康健身类第一，负责市场和运营的 Jake Castillo 讲过他们怎么投 Apple Ads，下面几条都是他讲的

1. 从竞品词开始投

先别急着买「screen time」这种品类词，先买「Opal」「One Sec」「ScreenZen」这种竞品名字。竞品花了大钱让用户记住名字，你在用户安装前最后一秒出现，成本只是对方的零头

2. App Store 页面就是广告

这里没有视频 hook，也没法测缩略图，用户看到的就是你的商品页，前三张截图比其他东西加起来都重要。截图写用户能得到什么，「Stop Doomscrolling Once And For All」比「AI-powered focus engine」好卖

3. 用上自定义产品页

一个 app 最多可以做 70 个版本的商品页，各有各的链接、截图和文案，还能绑定关键词，自然搜索也会展示对应的那一版 搜「screen time」的人看减少屏幕时间的截图，搜「dopamine detox」的人看多巴胺相关的，搜「Opal」的人看你为什么比 Opal 好

4. 账户拆成四类

探索新词、品类词、自己的品牌词、竞品词，各开各的计划 先用精确匹配，广泛匹配只放在探索计划里。一个词在精确匹配里跑赢了，就在探索计划里把它设成否定词，免得自己的计划互相抬价 出价先低一点，等 24 到 48 小时再慢慢往上加，Apple 比 Meta 慢

5. 别只投美国

加拿大、新西兰、英国、澳大利亚竞价的人少，点击便宜，有些 ROAS 比美国还好。都是英语市场，商品页和截图基本不用重做，测起来成本很低

6. 自己的品牌词一定要买

你能截竞品的流量，竞品也能截你的。达人视频一发，搜你名字的人几小时内就会涨，品牌词计划要在视频发出去之前就开好、充好钱

7. 只看收入和 ROAS

CPI、CTR、CPC 再好看也没用。一个词安装成本贵一倍，带来的用户值五倍，它就是更好的词。便宜的低意向安装能让后台很好看，订阅收入却纹丝不动

8. 把关键词当成一个投资组合

探索计划冒出新词，就挪进单独的精确匹配计划，按收入看行不行，跑赢的升到主力计划再加价，一直这么循环 要放量的时候，多开几个国家、多测新词、多做几个竞品计划和自定义产品页，别光往上加出价

截图做得好还能省钱。按 Jake 的说法，转化高了，Apple 会判定你更相关，同样的出价，每个用户的实际成本更低，设计师的活最后会算进你的获客成本里

一个人怎么带约30个 AI agent 干活？日本作者 mitsuki_ailover 把做法摊开了：他在 Grok Bot 里建了约30个分角

yibie @yibie

一个人怎么带约30个 AI agent 干活？日本作者 mitsuki_ailover 把做法摊开了：他在 Grok Bot 里建了约30个分角色 agent，从生活助理、商务助理、CTO 接口，到项目客户、补贴、内容和产品各有专人。agent 们共用一台云电脑，聊天窗口和各自记忆分开，姓名和重要政策这类人人要知道的事实放在共享记忆里。

先把「发生了什么」说清。他一整天并行派单，agent 负责从确认需求到执行，他只做思考和最终决策。编码流程是：CTO 接口 agent 先看进度、分发请求，派给远程服务器 tmux 里的 omp（编码 CLI）；实现中要拍板时，CTO 接口不自己决定，把问题退回发起 agent，由他和那个 agent 一起定。除 omp 外还并用 Claude Code 和 Codex，把调研、实现、评审的入口分开，降低自己的确认成本。

指令不用键盘。他全程用 Aqua Voice 语音输入，以零打字为前提，移动中也能派活，早上8点时段发出第一批任务，夜里11点后收工。为了配合语音，agent 必须按固定格式产出，比如「建草稿」或「把问题做成卡片回传」。

让这套东西不散架的是几条规则，比机制更重要：

1. 对外通信一律要他点头。邮件、发票、社媒帖文 agent 都不能自己发，只能起草，他批准后才出去。他说这是信任的地基，不会为了省事放松。

2. 问题一次只问一个，用选择卡。他主要在手机上处理工作，agent 不甩长文，而是把确认做成单题选择卡，看完选完再进下一题。他的体会是一次可靠地决定一件事，比被一口气问10个问题更快。

3. Notion 当枢纽。会议记录集中放 Notion，决策也留在各 agent 自己的记忆和聊天里，目的是减少事后翻找。

他说最大的坑是分工和指令：谁负责什么一旦含糊，事情马上串线；花时间最多的就是划清角色、统一指令格式。

我的判断：这条最可抄的不是30这个数字，而是「人当评审部」这一条。30个 agent 是结果不是起点，他给三类人的起步建议也都收在一个动作上——公司工程师先定一个统一入口 agent，自由职业者头一晚把调研和起草挂出去、早上只做评审，非工程师用母语说需求要草稿，但从第一天就立死「对外发送必须本人批准」。没有这道批准门，agent 越多，错发和串线的面越大；有了它，人才真的只剩判断。

Ask @bot to read this post and set this up:

• Start with one bot. Call it Chief of Staff and tell it the job is to spot things before I do. Add a second bot when the first one is doing something every day.

• Put your logins and cards in the Vault before anything else. Without it, most tasks end with "I can't sign in".

• Set one routine. Sunday 6pm: read every bill and renewal from this week, build a Page of what's due, what went up, and what to cancel.

• Let it make the calls. Cancelling, rebooking, chasing a refund, asking if a prescription is ready. Tell it to say it's calling for you and to send you the summary.

• Anything you've explained twice, tell it to save as a skill. "Here's how I want the shopping list" then gets done the same way every time.

• Give it its own email address for sign-ups, quotes and deliveries, so the confirmations don't land in yours.

• End anything that costs money with "build it, show me, wait." It stops and asks.

If you only do two, do the Vault and the Sunday routine.
