Google just open-sourced the method thousands of its engineers use every

Alex Prompter @alex_prompter

Google just open-sourced the method thousands of its engineers use every day to stop AI doing sloppy work.

It's called the Elephant-Goldfish Model. Google built it for code, and it works for anything you ask an AI to plan or write.

The chat that plans never builds. A second chat that hasn't seen the conversation checks the plan.

How to run it in ChatGPT, Claude or Gemini:

1) The elephant. Open a chat and talk through the thing you want: the trip, the business, the kitchen, the essay. Tell it: "No output yet. Ask me questions until you could write the brief yourself." Give it 20 minutes.

2) The brief. "Write a one-page brief: what I want, why, what's already decided, what's still open, and the steps in order." Read it, fix what's wrong, copy it.

3) The goldfish. Open a new chat with no history (Temporary Chat in ChatGPT). Paste the brief and nothing else, then run three checks:

"Summarise this back to me in five lines, as if you're the one doing it." If it gets it wrong, fix the brief.

"You're the most sceptical person in the room. List every assumption here that isn't proven, and the three places this goes wrong."

"Could someone start step one right now with only this page? If not, what's missing?"

4) Fix the brief with what the goldfish found. Paste it into a chat and say: build it.

The first chat has been talking to you for 20 minutes and fills every gap with what it thinks you meant. The second chat has only the page in front of it, so it can only find gaps that are on the page.

Google's line on the goal: the AI produces what you wanted the first time you press enter.

The plugin is free on GitHub, search elephant-goldfish-model.

神经网络的权重一直是一串人类看不懂、只能交给优化器去调的数字。MIT CSAIL 的一篇实验文章说，这件事开始变了：前沿大模型能直接读写权重。他们管这个叫权重空间编程（Weight-Space Programming）。

做法是把一个网络的原始权重直接贴给 GPT-6 Astra，用自然语言提目标，比如「这个网络被训练来玩什么游戏」「把它修好」。它不准写训练循环，不准跑梯度下降，很多实验里连环境反馈都没有，只能靠推理判断每个部分在算什么，然后直接改数字。

证据分三类。

1. 读。四个结构完全相同的 MLP（17253 个权重），分别用 PPO 训来玩 Breakout、Pong、Pac-Man、Freeway。不告诉它候选游戏，Astra 看权重全部答对。它看的是第一层输入通道的权重集中在哪：Breakout 的智能体权重压在底排，像一块挡板。更难的一次，他们把小语言模型的输入层和输出层都抽走，只剩四个 transformer 块，权重里连哪个维度对应哪个字符都没有。它仍认出模型训练于 Python、罗马字日语还是英语，还找出了全部复制头，一个误报都没有。

2. 修。一个 PPO 训出的控制网络怎么都开不上斜坡，Astra 一次编辑 3.5% 的权重，成功率从 0% 变成 100%。受关注最多的一次是修 Qwen3.5-0.8B：要求在没有梯度的情况下提高数学能力。Astra 在权重里定位到造成推理循环的问题，Qwen 自己的 model card 也警告过这个毛病，随后改掉 0.016% 的权重。同样的采样设置下，MATH-500 从 7.9% 升到 48.1%，效果还外溢到指令跟随，IFEval 涨了 3 倍。

3. 写。在完全没有环境反馈的情况下，它从零写出会玩 MinAtar 小游戏的网络，表现超过 PPO 训了一亿步的网络。

我的判断：过去权重只能由 Adam 这类符号优化器写，人只能把偏好塞进训练目标。这篇实验若能被独立复现，修模型的动作会从「继续训练、等它自己收敛」变成「打开权重、定位病灶、做定向编辑」。现在还远不到那一步：被测的都是小网络，Qwen 那次也只有 0.8B，而 Astra 本身闭源，谁也说不清这些判断是真读懂了结构，还是别的机制。

Claude API Message Threads 公测：长对话少重发历史

宝玉 @dotey

Claude API 公测 Message Threads：长对话不用每轮重发历史，回复更快，价格不变

Anthropic 今天给 Messages API（开发者调用 Claude 的主要接口）上线了“消息线程”（message threads）公测：服务器替你把对话暂存几分钟，下一轮只需要发新消息和上一条回复的 ID。

以前这个接口不记历史消息，每次请求都要把之前所有消息、工具返回的结果从头再发一遍。Agent 一次会话可能发几百个请求，对话涨到几十万 token 后，光是重发就会拖慢 Claude 开始回复的时间。

Claude Code 已经给大多数用户默认开了这个功能。官方数据：50 万到 100 万 token 的请求，从发出到 Claude 开始输出的等待时间（中位数）缩短约 35%；长对话里，单次请求的大小（中位数）从约 800 KB 降到 1.8 KB。

【要多花钱吗】

不用，但也省不了钱。按标准 token 价格计费，速率限制不变。请求虽然变小了，Claude 每轮仍要读一遍完整对话，消耗的 token 和以前一样。

【和提示词缓存有什么区别】

提示词缓存（prompt caching）让服务器不用重复处理已经读过的内容，命中缓存的部分按更低价格计费，省的是钱和计算。消息线程省的是上传，你不用再把整段历史传过去。线程不会自动帮你做缓存，缓存断点还得自己设，官方示例里两者是一起用的。

【开发者怎么用】

在请求里加 thread 参数和 beta 请求头（message-threads-2026-08-12）。第一轮照常发完整对话、系统提示词和工具定义，标记为新建线程；之后每轮只发新消息，带上上一条回复的 ID。

线程 5 分钟没有新请求就过期，接口返回 404，这时要用你自己保存的完整对话重新建一个线程。所以本地仍要留一份完整记录，官方 SDK 的辅助方法能自动处理这一步。

线程中途不能改系统提示词和工具，模型、思考设置也要和第一轮一致，想改就得重开线程。线程数据加密存在内存里、不写硬盘，但它不支持零数据保留（ZDR）和 HIPAA 合规，对数据留存有严格要求的企业要留意。批处理接口暂不支持。

适合长时间运行的 Agent、操作电脑的 Agent（截图不用每轮重传），以及带大量文档、图片的对话。Claude 自家平台、AWS、Microsoft Foundry 和 Google Cloud（Anthropic 托管版）上都能用。

TensorAgent：本地多模态知识库先转文字再检索

yibie @yibie

本地给 agent 做多模态知识库，最容易被讲成玄学：把文档、图片、音频、视频塞进一个统一向量空间，agent 就什么都懂了。TensorAgent 作者在 r/LocalLLaMA 介绍的做法相反，朴素得多：每种文件先被转成文字，再在本机检索。

它怎么处理五种文件：

1. 文档和 CSV：抽出文本和结构化内容。 2. 图片：调用兼容的视觉模型，产出描述和画面里可见的文字（OCR）。 3. 音频：受支持的格式通过兼容的音频模型转写。 4. 视频：只对采样帧提取信息，音轨不索引。 5. 检索：默认 BM25，embeddings 可选。

作者特意划清一条边界：这不是把所有模态嵌进同一个共享向量空间。图片是视觉模型写出来的描述，视频是抽帧后的结果，音频是转写文本——进索引的都是文字表示，不是原始像素或波形。

这套设计里我认为真正可迁移的是两点。

第一，承认覆盖是不完整的。视频只看采样帧、声音完全不进索引、图片理解取决于视觉模型，所以“索引了一个文件”不等于“理解了里面每个细节”。知识库还必须在每个对话里手动开启，不是默认把整个硬盘交给 agent。把这两件事写明，反而比宣称全模态全理解更可信。

第二，搜索和取数是分开的两步。演示用合成的咖啡馆活动数据：PDF 写 15% 折扣，海报写 20%。agent 先用检索定位到这两份冲突证据，然后回到完整的销售 CSV 上做计算，最后给出带来源链接的行动计划。关键在于，算数用的不是检索回来的几行，而是整个原文件。检索负责找到证据在哪，原文件句柄负责让计算跑在完整数据上。自己搭 RAG 的人大多踩过这个坑：top-k 截出来的片段足够回答问题，却不够做汇总。

需要泼的冷水也有两点。演示是一段 83 秒的视频，用真实 UI、合成数据和脚本回复录制，不是实时模型运行，也不是基准测试；文中没有召回率、延迟或模型型号这类可比较的数字，计算只是用 Python 独立核过。帖里挂了 GitHub 和知识库文档链接，但这次抓取拿不到具体地址，我没能读到代码和文档，无法核实工程实现。

我的判断：这更像一份架构取舍说明，而不是可量化的产品评测。价值不在 TensorAgent 本身有多强，而在它把本地多模态 RAG 该说清的事说清了——异构文件降级成文字、明确标注哪些信息丢了、检索与原文件访问分离。照这个思路，用 BM25 加可选向量、视觉和语音转写管线，自己也能搭一套。

公司大脑会过期：按工作流接系统源，别堆检索库

Alex Prompter @alex_prompter

Companies keep asking how to build one place where an agent can read everything the business knows.

I haven't seen one that works the way people imagine. That includes our own company.

The systems of record already hold different parts of the picture. The CRM knows the customers, the billing system knows the invoices, and the ticket system knows what broke.

An agent can do useful work when it can query the right source for the task and someone makes sure the information is current.

A single "company brain" starts going stale as soon as you build it. Documents age. Two versions of a policy sit next to each other. The agent has no clear way to tell which one applies.

Putting those documents into a retrieval index doesn't settle their authority. Retrieval can find a passage. Someone still has to decide whether that passage should govern the work.

For each workflow, I'd answer: 1. Source of truth: which system or document is authoritative for this question? 2. Version and effective date: which policy applies to the case being handled? 3. Permissions: is the agent allowed to retrieve this information for this user? 4. Provenance: can a reviewer trace an answer back to the source it used? 5. Ownership: who updates the material when the business changes? 6. Evaluation: which representative questions will show whether retrieval is returning the right evidence?

We start smaller. Each workflow gets the knowledge it needs and an owner responsible for keeping it accurate.

An onboarding agent needs the onboarding policy and relevant CRM records. Giving it the entire company archive adds more material to search without necessarily adding useful evidence.

I would also give it a way to say that the source is missing or contradictory. A confident answer to an unresolved policy conflict doesn't help the person responsible for the decision.

One brain for the whole business may be a reasonable long-term goal.

You don't need it to get your first useful agent into production.

PE 向组合公司引入 AI 伙伴：先钉一个具体问题再交付

Alex Prompter @alex_prompter

PE operating partners often ask me how to introduce an AI partner to a portfolio company.

The least useful introduction is a vague one: "Meet Limestone, they do AI."

The CEO takes the call, everyone agrees AI matters, and two weeks later the interest has faded. Portfolio companies are busy. AI gets attention when someone connects it to a specific problem worth solving.

A menu of services won't do that for you. The operating partner's useful contribution is helping the company identify where to look.

Here's the sequence that works:

1. Pick one portfolio company. 2. Name one problem: call-to-cash at an industrial company, billing at a healthcare company, or reorders that customers still have to phone in. 3. We scope it for free. 4. We ship it. If we don't deliver, they don't pay. 5. Make the next introduction with a result attached.

Before the first build, I'd want three things made explicit:

> Process owner: who can show us how the work happens and make decisions when it needs to change?

> Baseline: how long does it take today, how often does it go wrong, and how much human effort does it require?

> Acceptance criteria: what observable result will count as delivery?

Without those, even a technically impressive pilot can leave everyone arguing about whether it helped.

My first filter is the customer touchpoint. Will this make onboarding faster, get an answer to a customer sooner, or remove a delay they keep chasing?

That gives the business a reason to participate. It also gives the operating partner something concrete to discuss with the next company.

Our best introductions have started with a nudge: look here, this is where it hurts. A CEO who knows the roadmap is stuck gives us somewhere to start.

You can assess repeatability across the portfolio once the first workflow works. A shared problem doesn't mean every company has the same systems, permissions or exceptions.

If you're introducing vendors across a portfolio, a one-line description of the problem is worth more than the warm introduction.

不训练、不算梯度，GPT-6 Astra 直接改了另一个模型的权重：只动了 Qwen3.5-0.8B 0.016% 的权重，MATH-500 数学正确率从 7.9% 涨到 48.1%，约 6 倍。

这是 MIT CSAIL 四位研究者 11 月 2 日发的博客，他们把这叫“在权重空间里编程”：前沿大模型可以像读写代码一样，直接读懂、修改、甚至从零写出神经网络的权重。

过去的常识是，权重是训练出来的，人看不懂也没法手改，想改模型只能再训练。这项工作把原始权重直接交给通用大模型，让它自己读、自己改。

几个实验： 只看权重，不给游戏名、不给工具，Astra 认出了四个结构完全相同的游戏网络：打砖块、乒乓、吃豆人、过马路。

一辆训练了 10 亿步、256 次全失败的仿真小车，Astra 看了权重和一次失败录像，一次回复改了 3.5% 的权重，之后 1,024 次全部成功。

从零写打砖块网络，没有数据、不能试玩，一次写成，得分 517.4，是训练 5 亿步的强化学习网络（25.3）的约 20 倍。另外两个游戏没超过训练 5 亿步的版本。

这要允许 Astra 拿练习题试跑 50 次。只试 10 次或 25 次，循环基本没消失。

换成很少循环的 Gemma 3 270M，同样的方法没带来提升。作者的结论是：改权重能去掉挡住能力的障碍，加不出模型本来没有的能力。

Chandan Singh 也公开了类似实验：Claude 在加法、排序等 10 个算法任务上直接写出小模型权重，最多 3 次就全部 100% 正确。他的报告也记录了，有一个任务里 Claude 用测试集数据做了拟合，违反规则，那个结果被判无效。
