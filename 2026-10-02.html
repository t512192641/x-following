Claude Code 中的 Mods 升级：它允许通过 JavaScript 或 TypeScript 模块重写或替换部分行为，甚至绘制自定义 UI。

Claude Code 的 Mods 是会话内运行的小插件，让你按自己的工作习惯定制行为和界面：

输入框上方多一行用量：比如你可以这样描述需求：“在输入框上方加一行上下文用量，快满时变色，显示最近变化”。Claude 生成这个 Mod，你允许在当前会话热重载（保存代码即可生效）后，输入框上方就会出现一行每轮更新的用量显示；你若接着说“把暴风雨门槛从 75% 改成 70%”，保存修改后的代码，新的阈值就会生效。

删文件前，先看清会删什么：装上 Blast Radius 后，在执行删除 build 目录前，界面会打开面板，列出将删除的文件和占用空间，等待你按下数字键选择 Proceed 继续或 Cancel 取消。

改完后，逐项看哪里变了：装上 Replay Theater 后，一轮交互改完多个文件，输入框上方就会出现回放提示；只需按下 r 键或输入 /replay，即可在侧边面板逐项翻看每次编辑前后的差异（diff）。看完关闭面板即可，文件保持修改后的状态。

M. @wlzh

WiFi Calling 想拉起来，光改定位没用，顺序和开关一个都不能错。

国产Android普遍不行，iPhone的完整流程是这样：

1. 先把手机切到飞行模式。 2. 关掉你要用的那张卡。eSIM 就在设置 → 蜂窝网络 → 找到 → 关闭；如果你用的是白卡，那就是关 SIM 卡本身。这一步是整个流程里最容易被跳过、也最关键的：我试过卡不关只改定位，WiFi Calling 怎么都不起来。 3. 关掉苹果定位。 4. 打开小火箭，把定位改成《特定地区》。 5. 重启手机。重启完先开小火箭，连上《特定地区》的节点。 6. 小火箭的代理模式切成 tun，原来填的 http 那栏改成 none。 7. 在隧道设置里把“包括所有网络”和“包括蜂窝服务”都打开。 8. 此时再打开苹果定位，打开苹果地图确认位置落在《特定地区》，顺便看一眼节点 IP 是不是也在同一地区。这两个对不上，后面基本白搭。 9. 最后把 eSIM 或 SIM 卡重新启用，启用的路径和关闭时一样。等一会儿，WiFi Calling 就起来了。

核心逻辑是关着卡的时候把位置环境做干净，再让卡“重新出场”时读到的是假位置。顺序乱了就得重来一遍，第 2 步和第 8 步是两个卡点。

Cloudflare 上线了全新 CLI：cf。

光名字就赢了，比 wrangler 更短、更好记、更好敲。

🙋‍♂️ 为什么要再造一个 CLI？

Cloudflare 统计显示：上周 wrangler 的调用里，有 48% 来自 agent。太合理了。现在很多事我也几乎不亲手跑命令了：建 D1 / R2 / KV / Workflow，配域名、部署站点、拉日志、排查问题，都是 agent 直接通过 CLI 代劳。

那为什么要重做？我猜核心原因之一是：wrangler 的设计对象主要是“人”，而 cf 开始明显面向“agent”。比如它默认输出 JSON，更利于机器消费结果，减少上下文浪费，也更适合自动化链路。

我的结论：开发工具正在把 agent 当作第一用户。命令是否易发现、输出是否易处理、配置是否可类型检查，越来越关键。

After quitting our jobs and failing twice, we finally built a product doing $5k MRR and got into Y Combinator. But halfway through the batch, we pivoted.

Voice AI testing was another.

The more time we spent on it, the more convinced we became that it was a much bigger problem, and one we were far more excited to spend years working on.

So we changed direction during the batch. I think founders can overvalue traction.

Revenue proves an idea is working. It doesn’t prove it’s the best company for you to build.

Working on multiple ideas gave us enough distance to see that. It also made it easier not to force something just because it was the only idea we had.

Paul Graham says to treat a startup idea as “a hypothesis rather than a blueprint.”

That’s how we found Cekura. We kept putting ideas into the world and stayed willing to change our minds, even after one started making money.
