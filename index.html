decidr 的作者 Anmol Sharma 做了个 learnc，把 C 代码里那些手挑的常数交给梯度下降去学，然后把同一个 C 文件还给你，生产里不留任何新依赖。

《learnc：自动调优你 C 代码里的魔法数字》

每个 C 代码库里都塞满了手挑的常数：阈值、表、权重、截止值。learnc 从数据里把这些常数调出来，再把同一个 C 文件还给你，只是数字更好了。不用重写，不在生产里跑运行时库，也不塞神经网络。只是一个更小的 diff。

learnc tune score.c --data https://examples.pt/ --tune encoder.h:YQT,UVQT --out tuned/

在真实、未改动的 C 代码上得到的结果

· JPEG 编码器（stb_image_write.h）——调了它量化表里的 128 个数字——在它没见过的数据上：同等画质（SSIM）下文件小 9.1%，mozjpeg 的表是 2.7%。标准 JPEG：每个解码器都会读它 · Google 的 WebRTC 语音活动检测器——调了 vad_core.c 里每一个常数——在 LibriParty 上 F1 从 0.810 到 0.859，准确率从 0.816 到 0.858 · 一个 2×2 矩阵乘——84 个系数——只从样例里就重新发现了 7 次乘法的 Strassen 型算法 · 排序网络——每一步比较哪些元素——为 4 个和 5 个输入找到可证明最优的网络

每个结果都能在一台笔记本的 CPU 上几分钟跑完，并且可以从 examples/ 目录复现。

输出是你自己的文件，只是数字变了。下面是 learnc 给 Google 的 WebRTC VAD 写出的 diff 开头。

为什么做 learnc

· 作用在你已有的代码上。按名字指向常数：文件级的、函数里的 static、或者头文件里的。你的文件永远不动，调完的副本只差那些变了的数字 · 任何能编译的 C 都行。指针、结构体、malloc、文件、qsort 回调、sscanf、没有源码的库。clang 和 gcc 能构建的，learnc 就能调 · 优化你真正在意的东西。你的评分函数返回一个数：错误率、文件大小、延迟、与预期输出的匹配度。learnc 去最小化它 · 生产可用。带早停的留出验证、一个把你拉回原值的力，以及最后一轮把所有没帮上忙的改动回退掉。diff 里只留下有意义的改动 · 零运行时开销。输出就是带常数的纯 C。用任何编译器、在任何平台都能发

用途

· 压缩：JPEG 与 WebP 的量化表、zlib 匹配参数、编解码器的码率控制常数 · 音频与信号处理：语音活动检测阈值、降噪、滤波器系数 · 启发式：缓存大小、排序与查找的截止值、评分权重、重试与退避常数 · 控制：PID 增益、物理与仿真参数 · 嵌入式和定点代码：Q 格式常数按整数调，保持原有类型 · 用 C 写的小模型：规则、决策结构，以及能编译成零依赖 C 的小网络

安装

pip install learnc

还需要系统里有 clang、llvm-link 和 gcc：

sudo apt install clang llvm gcc # Debian / Ubuntu brew install llvm gcc # macOS（把 $(brew --prefix llvm)/bin 加进 PATH）

Python 3.10 起。PyTorch 和 NumPy 会一起装上。要改 learnc 本身：

git clone https://github.com/devanmolsharma/learnc && cd learnc pip install -e ".[dev]" && pytest

快速上手：调已有代码

1. 看看有什么能调：

learnc constants encoder.c --cflags "-I include"

2. 写一个评分函数，接一个样例、返回一个要最小化的数，或者一个要匹配的结果：

#include "encoder.h"

esp32-iphone-agent：7 美元 ESP32-S3 让 AI 上手 iPhone（不装 App、不越狱）

M. @wlzh

7 美元，让 AI 真正"上手"你的 iPhone。

GitHub 上有个新项目火了：esp32-iphone-agent。思路野得很——不装任何 App，不越狱，不要 Mac 也不要开发者账号，就靠一块 7 美元的 ESP32-S3 开发板，让 AI 模型直接操作一台真 iPhone。

原理拆开看其实很优雅，分三块：

眼睛：iPhone 屏幕通过 AirPlay 投屏到电脑（用的开源 UxPlay），AI 看到的就是你看到的画面。

手：ESP32-S3 插进 iPhone 的 USB 口，伪装成标准 USB 鼠标键盘。打开 iOS 的辅助触控，鼠标移动变成屏幕上的小圆点，点击就是轻触，拖拽就是滑动。板子走 Wi-Fi 连电脑，电脑发 move、click、type 这种简单指令，它执行。

脑子：任意兼容 OpenAI 接口的视觉模型，云端 API 或本地跑的都行。规划器看屏幕定计划，执行器看每一步的新截图决定点哪滑哪。

效果已经能看了："打开白板画个笑脸"，它自己找 App、打开、用连续笔画出来；"定个每天早上 7 点的闹钟"，它打开时钟、拨时间滚轮、勾重复日期、保存。每一步的截图和落点都留在网页上，能回放。

有个细节很妙：指针是相对移动的，服务器每次点击前会"抖一下"指针，在投屏画面里找到它、校准位置，打偏了自己发现重试。

限制也有：密码输入、Apple Pay、DRM 视频这些界面投屏看不到；键盘只能输英文；横屏 App 暂不支持。

但方向是对的。以前 iPhone 自动化走 XCTest 那套，要 Mac、Xcode、开发者账号，免费账号签名 7 天过期。这个项目走"人走的路"——屏幕和指针，手机端零安装。两天攒了 700 多个 star。

刘小排 @bourneliu66

REA 只是一个Hype，不值得你浪费时间

最近REA爆火，好多自媒体博主在刷屏说，商业软件要完蛋了、商业软件都可以被逆向改成开源的。

好多朋友问我：小排哥，这个REA，你怎么看？ 我只能回答：我不看。

嗯，我也不建议你浪费时间。

下面说三点理由。

1. REA不是新的逆向技术，只是帮你使用别的逆向工具。

REA不是新的逆向技术！ REA不是新的逆向技术！ REA不是新的逆向技术！ 我先说三遍 因为让我感到意外的是，这么明显的事，90%的自媒体都没搞明白，我也真是服了。

REA的核心不是发明了新的逆向技术，而是让 Claude Code、Codex 这样的 Agent 能够自动使用已有的逆向工具。 这些底层工具很多早就存在了。REA的工作，是把专业工具的专业能力暴露给Agent。

2. 你在自媒体里刷到的很多出圈的逆向工程案例，并未使用REA

例如最近著名的游戏逆向案例：开发者 Maurice Heumann 通过多个 Agent 并行工作，还原大量 C++ 函数。 但他使用的是 Hex-Rays 官方 MCP，并不是 REA。 但是很多讨论把整个 AI 逆向浪潮的成绩归到 REA 身上。 那能怪谁呢，反正那些自媒体也没啥文化，他们的读者也没啥文化。 写的人不知道自己在写啥，读的人不知道自己在读啥。

3. REA 的GitHub星标数量明显异常，有主观刷数据的嫌疑

在我刚才核验REA的仓库，发现有16.8 万 Stars、4 万 Forks，但只有546 个 Watchers。 Fork/Star 比例接近 24%，相当不寻常。 老外不傻，早有别的老外发现了这一点。 评分增长异常、比例异常、大量评论一看就是机器人、一些贡献者的活动轨迹可疑。

我的几个判断

1. REA的热度很快就会迅速消退。你不需要关注它。直接屏蔽REA这个关键词，你什么都不会错过。 2. REA的本质是让Agent接管专业工具。Agent接管专业工具的趋势不会消退。

对自己有期待的朋友们，请找点正经事做吧。 数字泔水可以留给别人去吃。

Rich Hickey：「AI」不是工具——工具要你挥舞并积累技能，LLM 给的是自动化

yibie @yibie

'AI' is Not a Tool

Clojure 作者 Rich Hickey 把「LLM 是工具」这句话拆掉了：工具是你挥舞起来、并且始终在控制之中的东西，用它会积累技能；这几样 LLM 都给不了，它给的是自动化。

《「AI」不是工具》

（这条我一直在当段子讲，这里多说一点）

第一件事：「工具」这个词会不会有一个有意思的、能区分开来的、因而有启发性的含义？还是说，它只是个「任何有用的东西」的、平庸的替身？

我们把「工具」这个词留给 AI 巨头们用的那种意思吧——任何可以被利用的人或物。对他们来说，风投、政客、想当巨头的 CEO、软件开发者、乡村小镇，全都是「工具」。我衬衫前胸的口袋很有用（我得把老花镜搁在手边），但它不是工具。同理，快餐店的得来速窗口很有用，但不是工具（后面再说）。

「工具」的一些定义：

· 一种器具或工具，尤指握在手里、用来完成某项特定功能的 · 一件（像锤子或锯子那样）用手使用或操作的器械：手工艺人或劳动者在工作里用的器械

我最喜欢的一条：工具是你挥舞的东西。

· wield —— 使用（如工具或器械），尤指带着完全的掌控或力量：handle、manipulate、control

这里面尤其有用的是：

· 握在手里——既是控制和反馈的来源，也标志着使用这个行为的亲密 · 力量——力、能量的传递与方向、杠杆等等 · 控制——意图，以及对事件进程的持续引导

工具是你用它去做事的器具，它们不替你做事情。使用工具会培养、奖励，也常常要求专业与技能。技术与能量的持续施加，还有感官反馈，对专业的积累是必不可少的。expertise 来自 experiri，意思是「尝试」。

好的工具有很多 LLM 没有的性质——可预测、可靠、确定、功能有界，最好是简单的。

你挥舞工具时学到的东西，是关于世界、关于任务、关于你想做的事或者你想克服的局面背后那些物理与逻辑的。而且往往，也关于你自己。

作为一个做了一辈子工具的工具制造者和使用者，我知道工具是什么。LLM 不是工具。

控制、感官反馈、意图、亲密、持续引导、专业——这些在使用 LLM 时全都缺席。LLM 不是被挥舞的。LLM 是自动化。

· 自动化——（指设备或流程）几乎不靠人的直接控制、自行运转

得来速不是用来做菜的工具，它是用来避免做菜的自动化。同理，LLM 不是用来写代码的工具，它是用来避免写代码的自动化，是你把写代码这件事让渡出去的地方。

你不是在引导 LLM 的动作——你提出请求，它自行行动，没有你的能量，也没有持续的引导。这种请求与自动化的循环不是挥舞，不是控制，不连续，也没有反馈。

你用自动化做的事，不是去了解真实世界的真相，而是试图猜出某个自动机器当下这套细节，并努力去套住它们。比如点一个定制的汉堡（不要洋葱），好拿到一个现做的。或者，往 voodoo.md 里塞进正好对的那几句咒语。你离「自己学到的一切被最新算法作废」只差一次软件更新——一个被拿掉了洋葱的、湿冷油腻的汉堡。你换来的是：从和世界打交道，变成为一台任性无常的机器人打工。

把「工具」和「有用」随随便便画等号，是个错误。比如说，「这篇论文不是 LLM 写的，我只是把它当工具，读了并总结了几篇研究」。可你并没有挥舞它去读那些论文，就像你挥舞一台 Kindle 那样。是它在读论文，不是你。

让渡掉「读书」这件事，你错过了什么？几乎是全部。首先，你错过了向那些会写的人学怎么写。你错过了学会把论证组织出来。你错过了注意到一些东西。你错过了用素材把自己的背景心智塞满，好让新想法长出来。你错过了对某些作者建立信任、对另一些保持怀疑。你错过了所有的玩笑。你错过了所有的边角。你错过了学会怎么思考。

工具不会「失准」，不会「失控」，不会「逃出围栏」，不会「密谋」。

LLM 不是工具。我知道很多人说「只是工具」，意思不过是「它们取决于你怎么用」。可那不是真的。自动化有一些内在的性质，与工具不同——忽视这些性质，后果自负。

Rich
