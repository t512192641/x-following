它把这个过程暴力拆成了两个极端角色：

大象（Elephant）：长记忆。吃下你所有的业务背景、历史需求和全局代码，专门负责输出一份详尽的技术规格（Spec）。

1. 大象 Agent 负责铺全局、起草规格； 2. 金鱼 Agent 无情挑刺，把模糊地带全逼出来； 3. 你作为人类工程师，在最关键的架构节点拍板、批准 Spec； 4. 规格锁死之后，再放给模型去刷代码。

当你觉得困难的时候，说明不是你应该做的。

当你觉得写和审 Spec 很困难，说明你不应该做；你应该转向 Goal，让 Agent 从 Goal 中派生 Spec。

当你觉得写 Goal 也很累，说明你不该自己写，让 Agent 设置目标，你来审。

当你觉得描述要生成的图片很累，你可能已经通过表达对结果的预期，让 Agent 去生成了（它依然会有详细生图 prompt 存在，但作为内部过程，而非人机界面）。

因此，当你觉得记忆管理很困难，说明你也不应该自己做。

你甚至不应该对记忆有特殊对待，应该跟其它上下文一样，围绕特定任务和目标，提供原始材料和检索工具。

然后，最重要的是，不要期待 Agent 一次弄对、一次全对，而是靠循环反馈，在多次推进和纠偏中，将结果收敛于没有明显问题的可接受形态。

总的来说，当 Human in the loop 感到困难和痛苦，人自身成为瓶颈，意味着需要 Lift 到更外层，不要阻碍这个环节的 Agent 交付产能，不要让自己成为卡点。

最终我们常常 Human on the loop，偶尔 in the loop，不时被 Agent 的低级错误笑掉大牙，但总是可以纠偏。

Loop Agent 则更加端到端交付，通过 24 小时无间断工作的 n 倍算力投入，将中间误差从显著到不显著，从核心区域到边缘区域转移。

你的系统1比你的系统2，对 AI 有益。你的系统2比不上 LLM，所有技术细节/理论细节方面都比不上。

但你的系统1工作省力、可以做快速直觉判断，它指引了 Agent 收敛的方向。

你的系统2训练，是为了通过过度学习，将专业知识/审美压进系统1，从而使它具备特定方面的快速反应能力。

你的痛苦来自于你用自己慢启动的系统2，去扛端到端交付的某个节点，你的生理限制就是瓶颈所在。

你需要的是用你的系统2，为你的系统1去设计可观测、可验收材料作为任务目标。

再将你自己从端到端交付环节中摘出来，让 Loop Agent 接管。然后，用你的系统1省力的反馈，调教 Loop 的迭代方向。

这就是 HAI(Human-AI Interaction) 的演进方式。

Alex Prompter @alex_prompter

I went to film school and cut a film that sold to the New York Times before I ever used ChatGPT.

Every editor learns the same lesson in the first week: The first cut is a draft.

I run my AI work the same way. 7 checks before I trust anything Claude or ChatGPT gives me:

1. Ask where it got that. If it can't point to a source, a file I gave it, or its own reasoning, it's guessing. I type "show me what this is based on" and the answer usually changes.

2. Ask for the opposite case. "Argue the other side in 5 lines." If the counter-argument beats the answer, the answer was weak.

3. Change one input and run it again. Swap a number, a name, a date. If the output barely moves, the model skipped my input and recited a pattern.

4. Count the hedges. "Typically", "often", "generally" three times in one paragraph means it doesn't know. I ask for a version with no hedges and see what survives.

5. Check the numbers by hand. Any percentage, price or date gets a 30-second search. Models round, invent and mix up years. This check has caught more mistakes than the other six combined.

6. Read it as the person it's for. A customer, my accountant, my mum. If one of them would say "wait, what?", it isn't done.

7. Sleep on anything that goes out under my name. Posts, emails, offers. I cut it again in the morning and it comes out shorter 9 times out of 10.

The model gives you a first cut but you still do the edit.

今天拆一个模型，CPA。很多人听过这个词但不一定真正理解它背后的逻辑。 CPA

象骑士Hack @xiangqishi

今天拆一个模型，CPA。很多人听过这个词但不一定真正理解它背后的逻辑。

CPA，Cost Per Action，按行动付费。用户完成了一个指定动作，推广者就能拿到一笔收益。

这个模型为什么存在？你从平台的角度想就明白了。

一个网盘平台要发展用户，有两个选择：一是自己花钱投广告，二是让别人帮它推广，按效果付费。

自己投广告，成本不可控。投了可能有效果，可能没效果，钱花了就花了。你看不少平台砸了几千万广告费，转化出来的活跃用户少得可怜。

但如果让别人帮推广、按效果付费，就不一样了。只有用户真的来了、真的注册了、真的用了，平台才付钱。这对平台来说是零风险的获客方式。

所以CPA的本质就是平台把获客成本直接分给帮它获客的人。

这意味着什么？意味着你赚到的钱是平台获客预算的一部分。这笔钱平台不给你，也要花在广告上。给你反而更划算，因为效果可控、成本透明。

网盘拉新就是典型的CPA模型。用户注册了有拉新收益，用户转存资源有转存收益，用户开会员还有额外分成。每一层都是按实际效果付费的，平台不会白白多给你一分钱，但你做了它就给你。

理解了CPA模型，你就理解了为什么这个事情是可持续的——因为平台永远需要新用户，这个需求不会消失。只要有用户增长需求，你的位置就在。

这不是运气，是结构性机会。
