中型公司做 AI 转型的 15 个错误：先招一线而不是先设负责人，先做一个工作流而不是十个试点

Alex Prompter @alex_prompter

15 mistakes mid-market companies make with AI transformation:

1) Hiring a "head of" first. I did this at my own company, and it cost about eight months per failed cycle. Hire the person in the trenches first, and the manager later.

2) Running ten pilots instead of one. One workflow, one month, then decide.

3) Letting an agent write code before anyone writes the spec.

4) Calling an LLM for a rule you could write down. That's deterministic code.

5) Testing on invented examples. Your team's own wrong answers are the best test set you'll get.

6) Replatforming before counting the customers on the old system.

7) Switching the old system off on day one. Keep it alive and build the new one in parallel.

8) Staffing it with a big team. Small teams ship. One logistics rebuild was in production by month 6 with 2 engineers.

9) Measuring how much code got written. The bottleneck moved to reviewing it.

10) Letting AI code ship without a senior engineer reading it. On that rebuild, about 90% of the code was AI-generated, and a senior engineer reviewed every PR.

11) Giving a review agent merge rights. At a US healthcare data company with 100 developers, the PR review agent is advisory only and never had them.

12) Putting safeguards in a prompt. On a patient-billing voice agent we built, the identity check, quiet hours, and the handoff of disputes to staff all live in code.

13) Buying seats and calling it a transformation.

14) Treating it as a tech rollout. Change management is a people problem more than a tech one.

15) Waiting for a magic pill. There is no magic pill. Hard work, care, and effort.

Alex：100 人医疗数据公司先统一 Claude Code 插件和规范，再上只能建议、不能合并的评审代理

Alex Prompter @alex_prompter

一家大约 100 名开发的美国医疗数据公司请 Alex 帮工程组织把 AI 用对。工具已经有了，但各团队各用各的，花费和模型权限也没有统一管理。对方以为会先上智能体，他们却先做了一个全公司统一的 Claude Code 插件：按该公司规范配置，装到所有人机器上，带 20 多个命令，覆盖搭新接口、查授权、写测试、修失败的 CI、把 PR 整理到可评审。每人第一天拿到的是同一套标准。同时在全公司推行先写规格、测试先行、以及哪些地方必须人来拍板。之后才引入代理：一名工程师进到真实团队当 AI champion，在真实工单上做，并把经验写回手册；所有模型调用走同一个网关，带密钥、预算、审计和脱敏。流水线上的第一个代理只评审拉取请求、只给建议，从来没有合并权，每次仍由人合并。Alex 的结论是：如果团队还没有同一种工作方式，每多一个代理只会学会一种不同的坏习惯。
