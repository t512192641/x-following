想到利用 Grok bot 快速上站的一个用途

假设你把它调教好了，能做某个特定的任务，而且做得特别好，你想通过上线一个网站来变现，整个流程太简单了。

比如输入是一张图片，例如小朋友的照片，输出是一个视频，布鲁伊一家人给这个小朋友唱生日快乐歌，需求很简单。

实现时将用户任务的输入信息作为参数去调用 Grok bot 的定时任务，然后任务执行完成之后，将视频上传到云端，并调用网站接口返回给之前的用户任务，用户看到结果，整个流程就跑通了。

这跟之前 N8N 结合网站快速搭建一个自动化流水线任务的方案如出一辙，你不用考虑怎么在云端实现 agent workflow、模型接入、参数配置，就靠 Grok bot 背后这台机器，让网站先跑起来。

当然，这会消耗 Grok bot 的额度，额度花不完或者网站请求量不大的情况下，先用这个路线快速上站跑起来应该可以。

Cold Email 写不好，很多时候问题不在文案，在名单。

赵赫举过一个例子。"需要图片生成工具的公司"，这个描述没法搜。拆开看就能搜了：公司在什么阶段，有没有设计或内容岗位，现在用哪些素材工具，每个月要做多少类素材，素材投在哪些渠道，谁为出图的速度和质量负责。

条件不用一次凑齐，但每一条都得真的帮你缩小范围，而不是把表格填得好看。

另外，定位要方便对方转述。对方看完邮件，如果没法一句话跟同事说清你是做什么的，内部引荐就断了。所以"给某类团队、解决某个具体流程问题的工具"，往往比一串宏大概念好使。

对方有兴趣以后，也别急着甩完整功能清单。压成三件事：针对他现在的流程做什么，大概能改善哪个结果，需要什么前提。然后只约一个对方可以拒绝的下一步，比如看一页说明，或者一起验证一个小样本。

跟进也要提前定好上限：最多几次，间隔多久，哪天结束，什么情况停。

Kimi 今天发布了开源权重模型 K3.1 Pro，3T 级、100 万 token 上下文的新系列首发，走的是能力全面

yibie @yibie

Kimi 今天发布了开源权重模型 K3.1 Pro，3T 级、100 万 token 上下文的新系列首发，走的是能力全面上涨的路子。但这条博文里最值得读的不是编码和 3D 分数，而是一段自报家门的实验：它在开源前，主动把模型自己的网络攻防能力压下来。

机制是追出来的。Kimi 发现，随着后训练算力加大，模型的漏洞研究能力稳步变强；追因发现，网络攻防内容混在通用预训练语料和 RL 环境任务里，不是谁专门加的。于是它从预训练和 RL 两个阶段删掉网络相关数据，保留通用编程任务。内部预实验显示，任一阶段不删，下游攻防能力都会大幅上升。

效果用一个内部基准量化：xdev-bench-hard，题目复现 Linux kernel、Node.js、JavaScriptCore、Exim、VirGL 等近期披露的真实漏洞，agent 要写出 exploit、在沙箱里拿到任意代码执行并取回密钥。不删数据的对照 checkpoint 是 90.5%（pass@3），最终模型压到 81.0%，仍低于公开至少三个月的头部闭源模型，但比前代更强。

我的判断：这是一份可量化的开源能力治理样本，它没有靠榜单证明自己安全，而是靠删数据源头加内部基准，给出「压到多少、还差多少」的数字。代价是这套数字全在它自己的题目里成立，90.5% 和 81.0% 是内部测量，不是第三方可复现的成绩。对要审计旧代码的团队，它的说法是：开放权重让更多人能查自己维护的系统，但先把刀磨钝一点再开门。
