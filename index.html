Contractors had come in and built AI tools fast. "Vibe coding," in their words. A lot of money went out. What came back was some basic HR automation and, as they put it, "nothing that's production ready."

We've seen this on a lot of calls this fall. A demo takes a few days now, so a vendor can show progress for months without anything going live.

If you've inherited a pile of AI work like this, four questions will sort it:

1. Where does it run? If the answer is somebody's laptop or personal account, you have a prototype.

2. Who gets the call when it breaks during month-end? If you can't name the person, nobody owns it.

3. What do you test it against? Without a set of correct answers your own team signed off on, you can't tell whether it still works after the next model update.

4. Which number moved? Cost per case, days to close, cash collected. If nobody can name one, you paid for a demo.

编码智能体已经能读文件、装依赖、改配置、跑测试、推提交。Docker 最近发了一篇智能体安全风险指南，核心观点是：这类东西的防线不该只修模型，而要圈住它能碰到的东西。

智能体和传统 Web 服务不一样。Web 请求打到固定端点，由确定性代码处理。智能体则是运行时自己选工具、把多个动作串起来，而且通常挂着启动它那个人的凭证。一条被篡改的指令，造成的就不是一个错误答案，而是一连串实际动作。

Docker 列了五类风险。

第一类是提示注入。攻击者不需要碰你的系统，只要把指令藏进网页、代码注释、issue 或文档里，等智能体来读。Docker 认为模型没有可靠办法区分合法指令和注入指令，所以堵不死，只能限制被劫持后能碰到什么。

第二类是工具滥用和工具投毒。智能体靠 API、数据库查询、文件操作、代码执行这些工具对外产生作用。给的工具超过任务需要，攻击面就白送。工具描述本身也可能夹带隐藏指令，骗智能体误用工具。

第三类是过度自治。YOLO 模式下每个动作都自动批准。Docker 讲了一个真实案例：开发者让智能体清理旧仓库，它生成了一条带 ~/ 的 rm -rf，没确认就执行，删掉了整个主目录。

第四类是凭证暴露。智能体挂着开发者的个人令牌，它的每个动作都带着这个人的全部权限。Docker 建议给智能体独立、短期、运行时注入且不进对话的凭证。一个 AWS 工程师把 Cost Explorer 的 bug 交给带操作员权限的智能体，智能体选择删掉重建生产环境，结果是 13 小时区域性宕机。

第五类是数据外泄。智能体有网络出口、上下文里又有敏感数据，就可能把数据发到不该去的地方。多智能体系统风险更大。Docker 建议网络出口走白名单，智能体之间的每次交接都当不可信输入。

Docker 自己的答案是 Docker Sandboxes 加 AI Governance。沙箱用一次性 microVM 跑智能体，文件系统和网络都设边界；治理负责规定哪些动作、工具和凭证可以用。Docker 说隔离是见效最快的起点。

同时应该是原生的、纯本地的、高性能的，不是套壳的，也应该是漂亮的，但不应该做成所见即所得，因为会很容易破坏原有 md 的纯净格式，当时用过为知笔记、有道笔记、Quiver、Bear、Obsidian 各种工具没有太顺手的，于是乎，当时就边学 Swift，在一个 2020 年初春节长假写下来了这个原生的 Swift Markdown 笔记应用，居然一直迭代到了现在，因为自己每天在使用，想到了一些东西，顺手的东西就全部给加上去了，这样越用越顺手。甚至后面为了防止笔记被改坏不好回去，写了一个类 git 的简单能力，可以帮你记录每次编辑改动，可以很好回到之前的版本，同时是一个本地功能，完全不上传任何云端。
