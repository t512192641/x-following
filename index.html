Pi Durable：可从崩溃恢复的长跑 agent 框架

VerySmallWoods @verysmallwoods

Pi 1.0 来了。那么 Pi Durable 是什么呢？

这是一个实验性的 TypeScript 框架，用来构建长时间运行、能从崩溃中恢复的 agent 应用。Pi 1.0 是在终端里交互运行的编程 agent，Pi Durable 则用来搭建各种 agent 应用。

https:// earendil.com/posts/pi-durab le/ …

核心理念：存储层加上一套运行机制，可以在一个 harness 里同时跑多个 LLM 对话。

它的组成部分： - Storage：支持内存、SQLite、JSONL，不依赖 Node API - Conversation：用户和 agent 的对话记录，可以在任意位置 fork - Task：持久化的工作单元，每一步执行前都会先存 checkpoint - Extension：把 system prompt、工具、hooks 和自定义 task 打成一个包 - Executor：执行环境可替换，可以是 Node、远程 VM 或沙箱

一些技术细节： - 进程挂掉之后，新实例会从 checkpoint 继续跑。中断的工具调用要么安全地重跑，要么告诉模型它被打断了。 - 应用状态存成带类型的 JSON 文档，和对话记录在同一次提交里写入，两者不会出现不一致。 - 工具可以创建自己的子对话（subagent），每个子对话都单独持久化。 - 远程客户端可以订阅每次提交的操作流，所以支持多人协作、中途加入，也能在 agent 运行过程中插入新指令。 - 上下文快满时会在后台自动做 compaction，也可以用 handoff 换一个新的上下文，旧消息仍然可以搜索。

安装： npm install @earendil -works/pi-durable

官方提供了两个示例： - 约 1300 行的旅行规划应用 - 一个实验性的编程 agent

开发者朋友们，目前 API 可能还会变喔。

我每天使用 Coding Agent，对这种变化很熟悉。 以前写代码最花时间，现在 Agent 一次可以生成几百上千行。代码生成速度上来以后，review、测试和 eval 占用的时间越来越多。数学研究也开始遇到同一个问题：证明可以批量生成，能判断它是否成立的人和验证流程没有同步增加。

由清华人工智能学院助理教授陈勇超（ @YongchaoC ）创立的超衍智能（ @apexin_ai ）最近公开了 5 项 AI 数学研究。

另外 3 份仍然标为候选论证：凸形 Nivat 猜想完整证明、Souto 猜想亏格二情形，以及 Kakimizu 复形可缩性。

合作数学家先选择有研究价值的问题，Apex 的 AI 系统并行探索并交叉检查证明路线。找到候选证明后，再由作者或合作数学家逐步核验，并为最终结论负责。

这 5 项研究中，一个已核验案例和一个候选论证案例，正好展示了这套流程的两端。 Halpern 迭代与高阶优化研究展示了这套分工。AI 找到了 Halpern 迭代与锚定张量法（Anchored Tensor Method，ATM）的组合路线，但初版子求解器包含三层循环。合作数学家随后把它简化成单层结构，并整理、核验完整证明。论文公开后，清华、北大和 Google Research 的研究者又沿着相关方向继续推进复杂度结果。

通过机器检查的是已经写入 Lean 的部分，并不等于整项数学结论已经得到完整验证。整条证明仍然引用 Colle 已发表的一条外部定理，这项输入尚未完成形式化。

机器已经检查了大量推理步骤。外部定理以及整套论证能否获得独立认可，仍然需要研究者继续核验。因此，官方仍把它标为候选论证，没有直接写成已经解决的数学成果。

每人一台虚拟机是什么概念？

以前这玩意儿只在企业内网给几万号人开， 现在 Meta 要给几亿消费者每人配一台， 这工程量真的没人干过。

沙箱一滴没漏，信息照样出去了。

所以 agent 的安全边界，从来不是它能不能被攻破，而是它该不该开口。

前者是基础设施问题， Meta 这种体量砸钱砸人就能解决， 这块它确实做到了行业最能打的一档。

后者是判断问题， 取决于 agent 怎么理解「对面这个人是谁、这件事能不能对他说」。

而这部分，现在没有任何一家公司有靠谱答案。

同一条信息泄露出去，严重程度完全取决于对面是谁。

而「对面是谁」，正是 agent 最判断不了的东西。

不过有3件事得说清楚：

1、这件事目前是转述 Threads 上的帖子，Meta 没有正面确认过，细节未必准；

2、但凡你想让 agent 真替你干事，它就必须能代表你说话，这个权限没法只给一半；

3、最难的从来不是技术，是真出事之后责任算谁的

我们习惯用「有没有被黑」衡量一个系统安不安全。

Muse 没被黑， 但它透露了不该透露的信息。

这两天在看 Pi 0.99 的 MCP 实现。 https://t.co/VSfEhE0Aoi

注意到 Deferred 模式里一个容易被忽略的问题：工具按需加载，可以减少首轮 Schema；但工具在第二轮加入后，会不会导致 Prompt Cache miss？ 取决于模型 API 是否支持对话中途增加工具。

`toolsAdded` 只是 Pi transcript 里的内部状态。真正提交给模型时，存在两条路径：

1. 支持 Tool Addition

Pi 会把新增工具转换成 `additional_tools`、`tool_search_output.tools` 或 `tool_addition`，插入工具被发现的位置。

已缓存的对话前缀 → tool_search → search result → 新增工具 → 后续对话

已有前缀仍然可以 cache hit。首次 miss 的主要是新增工具及其后的内容，不是整段 Prompt。

2. 不支持 Tool Addition

Pi 只能重算当前完整工具集合，把它重新放进请求顶层的 `tools`：

上一轮：tools[A] 下一轮：tools[A, B, C]

工具列表在靠近请求开头的位置发生变化。对于前缀匹配式 Prompt Cache，后面的对话历史很可能无法继续复用，形成大范围甚至完整的 cache miss。

工具删除或同名 Schema 重新定义也有类似问题。此时 Pi 无法安全地把变化追加在原来的时间位置，只能重新提交当前完整工具集合。

dontbesilent @dontbesilent

《公开 dontbesilent 写标题的方法论》

现在网上有大量教你写标题的黄金公式，也有各种“蒸馏”大 V 的标题然后帮你写标题的 skill

在我看来整个流程都不对，这里来记录一下我写标题的方法论

一、最大的问题

这里不需要你理解内容传播，我们只需要靠常识来判断就可以知道，当用户想让 AI 帮忙写一个好标题的时候，绝大多数用户输入的内容本身就是没有人愿意看的内容

这种情况下，无论是让 AI 来写标题，还是让精通内容的人类来帮你写标题，都只可能产生两个结果

要么是你得到一个索然无味的没有人愿意点击的标题，要么是你得到一个非常吸引人的标题，但这个标题和你的内容并不相符（也就是标题党）

所以如果我们假设用户已经把内容写完了，而这个内容又不能修改，在这种情况下，我们产出一个方法论或者一个 AI 技能包去帮助用户写标题，这件事本身就是错的（一个人极其擅长书写吸引人的正文，同时又不会写标题的概率有多高？）

二、我的流程

所以一个好的标题应该在用户的正文还没有完成，甚至是还没开始写的情况下，就要开始思考了

我最近在重新做 dbskill 里面的帮你写短视频开头和内容标题的 skill，它会一次性帮你把标题、封面和短视频开头都写好

原因就在于他真正的工作是帮你产出一个更吸引人的内容，如果这件事情可以完成 ，标题和开头就很好写；如果这件事情完不成，那后面神仙难救

所以这里面的合理流程应该是，AI 要引导用户说出他大概想写一个什么东西，他大概有哪些素材可以提供

从而发散出一些能够吸引人的方向和角度（大家喜欢管这个东西叫选题，但严格讲，应该是恩特曼的“框架”，或者是修辞学的“争点”）

发散出来的这些角度，有些角度可能是吸引人的，但是用户根本就写不了；还有些可能和用户的变现目标无关（这里可能出现各种各样的问题）

所以 AI 应该和用户商讨，在变现目标和用户能力还有流量层级三者之间去找一个平衡。一旦这个平衡点找到，我们就同时解锁了封面怎么写、标题怎么写、开头怎么写，以及整个内容的写作方向

【划重点】一个好的写标题的 skill 是应该帮助用户写作的，是因为这套方法可以帮助用户写出更吸引人的内容，所以标题才顺水推舟一般出现

所以请不要再蒸馏大 V 的标题了，这是一个错误的方向

我也会在近期开源一个同时帮你写封面、标题和开头的 skill

可以先看一个具体例子：PDF 填表。

Claude 懂不少 PDF 内容，但理解内容和直接操作文件，是两回事。

Anthropic 的 PDF Skill 里放了预先写好的 Python 脚本，可以读取 PDF、提取表单字段。 Claude 遇到对应任务时，可以运行这些脚本，不必每次重新生成一套操作方法。

这就是 Skill 的一种价值：把已有的经验、流程和工具，变成 AI 可以重复调用的能力。

那是不是必须会 Python，才能用 Skill？

如果只是使用别人已经写好的 Skill，通常不需要自己编写脚本， 但相应的运行环境需要准备好。

而且，代码并不是必需项。 最简单的 Skill，可以只有一个 SKILL.md，里面写清楚这项任务应该怎么做。

那和直接把说明贴进提示词，有什么区别？

你每次贴说明，它就跟着这次请求进入上下文，也就是 AI 这一轮能参考的信息。

Skill 则先让 AI 看见名称和用途，任务相关时才读正文，更细的资料再按需展开。 常用流程可以复用，不必每次重新交代。

但这里有个关键：AI 怎么知道什么时候该用它？

靠名称和 description，也就是用途说明，提供匹配线索。

别只写一个很厉害的 PDF 助手了。 要写清楚：它能做什么，以及什么情况下应该使用。

比如： 提取 PDF 文本、 填表、 合并文档； 处理 PDF 或提到表单时使用。

Skill 的价值，不在于文件写得多完整， 而在于它有没有让 AI 更稳定地完成你的任务。

Anthropic 今天给 Claude Code 推出了 Mod 功能。Claude Code 是 Anthropic 做的 AI 编程助手，你用大白话告诉它要做什么，它自己读代码、改代码、运行命令。

Mod 这个词来自游戏圈，玩家给游戏装 MOD，可以改画面、加道具、换玩法。比如我们以前玩过的《反恐精英》最早就是作为游戏《半条命》（Half-Life）的一个 Mod。

现在 Claude Code 也能这样改了。

Mod 就是一小段程序，用 TypeScript（一种常用的编程语言）写。不会编程也没关系，直接跟 Claude Code 说你想要什么效果，它会自己把 Mod 写好、装上，马上生效，不用重启。

【它是怎么起作用的】

可以把 Claude Code 干活的过程想成一条流水线：接到你的要求，交给 AI 模型思考，模型决定读哪个文件、运行哪条命令，某些步骤要先问你同不同意，最后把结果显示在屏幕上。每到一个环节，Claude Code 都会发出一个信号，表示“我要做这件事了”。Mod 守在这些环节旁边，可以直接放行，可以改一改再放行，也可以拦下来自己处理。

举几个例子。你的要求发给模型之前，Mod 可以自动补一句“请用中文回答”；Claude 要读的文件里有密码，Mod 可以先把密码涂掉；Claude 想运行一条可能删掉数据的命令，Mod 可以拦下来，让你再确认一次。

Mod 还能改屏幕上的样子，比如在对话旁边加一个小窗口，显示团队的代码有没有通过自动测试，或者在输入框上方加几个按钮。

Anthropic 自己也开始用 Mod 搭产品。Claude Code 自带的 /diff 命令（显示改了哪些代码）现在就是一个 Mod，你可以关掉它，或者换成自己写的版本。官方计划把更多自带功能改成 Mod，以后用户可以只留一个精简的核心，其他功能按需加。

安装方式和普通插件一样，在 Claude Code 里输入 /plugin 就能找到。需要 Claude Code 2.1.287 或更新的版本，功能默认打开。

【要小心的地方】

Mod 拥有和 Claude Code 一样的权限，中间没有任何隔离。装上一个 Mod，它就能读写你电脑里的文件，看到你存的 API 密钥（调用 AI 服务用的“账号密码”），看到你发的每一句话，还能不经过你就替你批准操作。所以官方建议只装信得过的人做的 Mod。公司的管理员可以限制员工能装哪些 Mod，Team 和 Enterprise 版还会默认先加载一个安全 Mod，防止其他 Mod 绕过公司定的安全规则。

【和 DeepSeek Harness 比一比】

今年 8 月 13 日，DeepSeek 发布了开源的 DeepSeek Harness，也是一个 AI 智能体工具，能写代码，也能整理文件、分析表格、做幻灯片，GitHub 上已经有 24 万多人收藏。它的口号是“一切皆插件”，连连接 AI 模型的部分、管理工具的部分，甚至负责“想一步、做一步”的核心循环，都是可以拆下来换掉的插件。

两家想做的事一样，都是让用户自己定制 AI 助手，起点不同。

DeepSeek Harness 从一开始就是拼装式的。代码完全公开，用的是 MIT 协议（随便用、随便改），后面接哪家模型也由你选，DeepSeek 的、别家的、自己电脑上跑的都行。它甚至可以把任务转交给 Claude Code 或 OpenAI 的 Codex 去做，再把结果收回来。代价是它还在开发者预览阶段，官方提醒后续更新可能和旧版本不兼容，今天写的插件过一阵可能就用不了。

Claude Code 是闭源产品，绑定 Anthropic 自家的模型。Mod 相当于在一个已经建好的房子上开了很多扇门，能改的地方越来越多，但房子还是 Anthropic 盖的。Anthropic 说要把自带功能逐步改成 Mod、只留一个小核心，这个方向和 DeepSeek Harness 的“一切皆插件”越来越近。

想换模型、从最底层改起，DeepSeek Harness 更自由；已经在用 Claude Code 的人，现在不用换工具也能做不少定制。
