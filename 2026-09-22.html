Claude Code 四种 loop：别选错循环导致早退或空转

Alex Prompter @alex_prompter

Using the wrong loop for a task is why agents either quit too early or run forever on something that should have ended in minutes. Claude Code has four loop types, and picking the right one depends entirely on how the task should end.

The turn-based loop runs prompt, context, action, response, and loops back through context and verification until Claude judges the task complete. It triggers on a user prompt and stops when Claude decides the task is done or needs more context. This is best for short one-off tasks that are not part of a routine, and it is worth reaching for custom verification skills through a SKILL.md file to make that judgment reliable.

The goal-based loop puts an evaluator model in the middle. Claude works, the evaluator checks against a goal, and if the goal is not met it sends Claude back to work, looping until the goal is met or a turn cap is hit. It triggers on a manual prompt in real time and is best for tasks that have a verifiable finish line. Reach for /goal, set it to something like ninety or above, and cap it at five tries so it does not spin forever.

The time-based loop is the simplest, an interval timer running a prompt on repeat. It triggers on a set time interval and stops when you cancel it or the work completes. This is best for recurring work or watching external systems, and it runs either locally with /loop or in the cloud with /schedule.

The proactive loop runs entirely in the cloud with no human present. An event or schedule triggers it, the main agent works, opens a PR, and a review step feeds back into the next trigger, continuing until you switch the routine off. This is best for recurring streams of well-defined work, and it takes /schedule combined with /goal and workflows to set up.

Stanford：人们如何把判断交给 AI（而不自知）

Alex Prompter @alex_prompter

Researchers at Stanford tracked how people are handing their judgment over to AI.

And most of them have no idea they're doing it.

The paper is called "LLMs as Oracles."

Myra Cheng, Dan Jurafsky and their co-authors borrow the idea from ancient Greece. People used to travel for days to ask the Oracle of Delphi what to do with their lives. Now the oracle is in your pocket, it answers in three seconds, and it never says "I'm not sure."

They analyzed 68,000 public prompts, then got 52 people to donate their entire private chat histories. That's 140,834 messages, going back to December 2022. They weren't counting questions about code or facts, but they were counting the personal ones. Does this text mean she's upset. Was I unreasonable to set that boundary. What should I do tonight.

先说我最在意的一件事

同一段我自己的口播，8.6 秒，每 640 毫秒出一次结果。左边 Whisper 走"每次把收到的音频整段重解一遍"的伪流式，13 步里改写了 7 次，屏幕上已经显示的 93 个字被重写过，"见面了"变成"在这边了"又变回来，最后一句停在"全程媒介一找"。右边 R2T2 是 0 次改写，提交出来的字一个没动过。

更有意思的是 8.32 秒那一帧。R2T2 内部其实已经猜出"全程没接"，但它只提交了"全程"两个字，把"没接"压着没放。0.6 秒后证据够了，提交的是"没截"，对的。它不是猜得慢，它是知道这一刻不该猜。

为什么我在意这个。给人看字幕，闪一下无所谓。但这段文字如果是喂给下一个模型的，比如同传、比如一个要执行动作的 Agent，前面的字一改，下游就得撤销自己刚做的判断。视频第三段就是这条链路，R2T2 每提交完一句，原文直接交给 T3PO，中间没有人工，也不用等整段说完。因为 R2T2 给出来的字不会再改，T3PO 拿到就能翻，翻出来的英文也不会再改。

Copilot、Cursor 也是这样的策略。

“临时上传”和“完整源码被保存”，中间有很大区别。

Trae的用户群里解释了这件事，几个核心意思：

第一，代码仅临时上传用于向量计算， 计算完成后明文代码即被永久删除 ，云端不会保留完整源码。

第二，Trae代码索引的上传范围有严格的过滤机制：

- 依赖目录（node_modules 等）、构建产物、二进制文件、图片、音视频、压缩包等，不传 ；

- 以. 开头的隐藏目录（包括 .git） ，不传 ；

- .gitignore 中列出的文件默认被忽略，用户还可在.trae/.ignore 中自定义额外排除规则；

- 单文件大小和行数都有上限。

第三，隐私模式控制的是对话内容是否用于数据分析和模型训练 ，与代码索引功能无关。

这也是它和前几天那些争议需要分开看的地方。
